# ApuDa V3 임상 안전 UI — 응급 분류 경고의 저장 의존성 제거

작성: 2026-11-16 KST · 범위: Draft 통합 PR #304 · 운영 배포 금지

## 확인된 안전 결함
기존 triage(silent)는 선택된 응급 증상을 저장하는 `save()`를 실행한 **뒤** 치료병원 연락 또는 119 안내를 표시했다. 저장 용량 초과(QuotaExceededError), V3 쓰기 충돌, 향후 IndexedDB Promise 거절이 발생하면 안내 표시 자체가 중단될 수 있었다.

## 수정
- `triage(silent)`는 먼저 현재 체크박스에서 응급 수준을 계산해 DOM에 즉시 경고를 렌더링한 뒤 기록 저장을 별도 비동기 처리한다. 저장은 응급 안내 표시를 차단하지 않는다.
- 빨간색 위험군은 `role=alert`, `aria-live=assertive`로 설정해 보조공학 사용자가 빠르게 인지하도록 한다. 노란색 또는 증상 미선택 상태는 `role=status`, `aria-live=polite`를 사용한다.
- `save()`가 동기적으로 예외를 던지거나 Promise를 거절하거나 `false` 또는 `{status:'conflict'}`를 반환하면 기록 성공으로 판단하지 않는다. 검토용 원문을 `ApuDaNoteUnsavedDraft`에 보관하고 안내 내용은 그대로 유지한다.
- 이미 쓰기가 차단된 상태라도 응급 분류 결과는 새 체크값에 따라 즉시 다시 표시한다. 저장이 차단됐다는 별도 안내를 보여 준다.
- `saveDistress()`는 기존 마음 온도계 점수/기록 필드 구조를 유지하면서 이미 검증한 `commitNoteMutation()`을 거치게 했다. 저장 확인 전에 '기록 완료'를 표시하지 않고, 오류 시 검토용 원문과 원본 기록을 보존한다.

## Chromium 자동 시험
- 신규 `tools/tests/apuda-note-v3-triage-safety-browser.py`는 임시 127.0.0.1 서버에서 **실제 V3 전체 HTML**을 불러와 가상 환자 자료를 테스트한다.
- 시험 범위: 빨간색 응급 경고가 지연 저장 완료 **전에** 표시되는지, 저장 Promise가 실패한 뒤에도 경고가 유지되는지, 항암 증상 경고/119 문구/접근성 역할, 용량 초과 동기 예외, 비저장 상태 응답, 이미 쓰기가 잠긴 경우의 응급 안내, 마음 온도계 성공/실패의 저장 시점과 원문 보존.
- 외부 네트워크, Google Drive, Service Worker를 차단하고 테스트 전용 브라우저 프로필만 사용한다.
- 실제 CI 실행 성공을 확인하기 전에는 신규 테스트 통과라고 주장하지 않는다.

## 잔여 위험
- 응급 분류 안내는 환자교육용 정보이며 임상 진단 또는 응급 구조 요청을 자동 대행하지 않는다. 사용자가 직접 치료병원 또는 119에 연락해야 한다.
- 실제 V3 저장 엔진은 여전히 `localStorage` 기반으로 일부 코드에서 동기식 저장 경로를 갖고 있다. 긴급 안내 표시 개선은 `localStorage` TOCTOU, 구형 탭, Service Worker 캐시, Google Drive 백업/prune 문제를 해결하지 않는다.
- 의료진·환자·보호자의 실제 사용성 감수와 Android/iOS 실기기 검증 미실시.
