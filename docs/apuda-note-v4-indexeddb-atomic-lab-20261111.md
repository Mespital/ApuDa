# ApuDa V4 동시 저장 보호 시제품 — AI 사전점검 기록

- 작성: 2026-11-11 (KST)
- 범위: V4 개발 전용 IndexedDB 합성 실험. 실제 환자 수첩 저장소 변경 **없음**.
- 연결 검토: PR #294의 `tools/tests/apuda-note-v3-cross-tab-race-diagnostic.cjs`에서 기존 `localStorage`의 마지막 검사 이후 경합을 재현함.
- 공개/배포: PR #292 초안(`Draft`, **Do Not Merge**)의 Netlify Deploy Preview에서만 사용하고 `main` 운영 반영 금지.

## 1. 구현

- `public-site/note-v4/atomic-lab.html`: 가상 데이터 시험 버튼과 결과. noindex, 제한적 CSP, 자체 스타일만 사용.
- `public-site/note-v4/atomic-lab.js`: 브라우저 IndexedDB에 실행별 임시 데이터베이스를 생성하고, 별도 연결 2개에서 동일 객체 저장소의 `readwrite` 트랜잭션을 경합시킴.
- `localStorage`를 조회하거나 기존 V3 수첩 키·로그인·실제 개인기록을 사용하지 않음. 시험 후 연결을 닫고 임시 데이터베이스 삭제를 요청하며 삭제 성공 여부를 화면에 표시함.

## 2. 시험 항목

1. 신규 기록 생성(리비전 0→1)
2. 같은 리비전에서 동시 저장: 성공 1건, 충돌 1건 예상
3. 후속 조회에서 승리한 쓰기의 최신 내용과 리비전 보존
4. 구버전 리비전(오래된 사본)의 복구 요청 거부
5. 쓰기 도중 트랜잭션 중단 후 이전 기록 불변
6. 임의의 미지 필드·복수 체온 값 등 합성 데이터 원문 보존

W3C IndexedDB 명세는 동일한 객체 저장소 범위의 `readwrite` 트랜잭션을 직렬화하고, 트랜잭션 실패 시 일부 변경만 저장하지 않도록 정의한다. 다만 브라우저의 영구 디스크 기록(Flush) 보장 및 기기 저장소 회수 위험은 별개의 검증 대상이다.

- 1차 출처: [W3C Indexed Database API 3.0](https://www.w3.org/TR/IndexedDB/), 2026-11-11 확인.

## 3. 남은 P0 후보 / 인수 조건

- 이 시제품은 **새 저장 규약의 가능성 실험**이며 기존 V3 앱에 연결되어 있지 않다. 따라서 PR #294의 다중 탭 손실 위험을 해결했다고 주장하지 않는다.
- 실제 적용 시 수첩의 **모든** 저장·복원·삭제 경로가 같은 IndexedDB 트랜잭션과 revision 검사를 사용해야 한다. 일부 경로가 옛 `localStorage`에 쓰면 충돌이 계속 발생할 수 있다.
- 기존 V3 `localStorage`는 명시적 백업 및 확인 전 절대 자동 삭제/전환하지 않는다. 무손실 단계별 읽기·전환·복구, 새 창/구형 창 혼용, 앱 종료, 저장공간 부족, 모바일 실기기, 사용자 이해도 검증을 먼저 수행한다.
- D05(개발·품질), D06(개인정보·보안), D04(접근성) 기준의 **AI 사전점검**만 수행. 실제 전문가·환자·보호자 리뷰/승인 자료 없음.
- P0 기록 손실 배포 차단은 위 인수 조건을 충족하기 전까지 유지한다.
