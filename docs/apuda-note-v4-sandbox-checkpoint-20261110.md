- 작성·검토: 2026-11-10, Asia/Seoul
- 모듈: `public-site/note-v4/v4-sandbox-checkpoint.js`
- 시험: `tools/tests/apuda-note-v4-sandbox-checkpoint.cjs`
- 모드: **AI 기술 사전점검**, 합성 환자 기록만 사용
- 범위: 실제 V3 기록, 운영 V4, 자녀 논술 기록, 구글 드라이브·Netlify·브라우저 저장소 모두 **비접근**
- 상태: **격리 메모리(Map) 모의시험 통과. 실제 영구 백업·환자 데이터 이전·운영 배포 아님**

## 왜 만들었는가

앞선 `v4-migration-rehearsal.js`는 새 V4 데이터를 생성하고 취소·되돌리기를 **문자열 반환만으로 검증**했다. 이번에는 별도의 작은 가상 저장소에 이전값과 후보를 순서대로 기록하는 상황까지 재현했다. **쓰기 순서와 실패 지점을 제어하는 결함 주입(Fault injection)**으로 기록 손실 위험을 살핀다.

브라우저의 실제 `localStorage`, `sessionStorage`, `IndexedDB`, 파일 또는 원격 저장소를 받는 매개변수와 호출 코드가 없다. 모듈 내부의 `new Map()` 객체 외에는 값을 쓰지 않는다. 이 Map은 탭을 종료하면 사라지는 가상 공간이므로 백업 또는 복구 저장소가 아니다.

## 시험한 순서

1. 사용자가 명시적으로 전달한 합성 V3·기존 V4 문자열의 SHA-256 및 건수 검증.
2. 가상 저장소에 **기존 V4 값**을 유지하고, 원본 V3·이전 V4·새 후보를 가진 **복구 체크포인트(Checkpoint)** 기록.
3. 체크포인트의 **재조회값(Read-back)**이 기록한 문자열과 정확히 일치하지 않으면 V4 후보 저장 금지.
4. 다른 작업이 V3나 이전 V4를 변경했는지 확인. 다르면 저장 금지.
5. 새 V4 후보를 가상 영역에 저장한 다음 다시 조회해 정확히 일치하는지 검증.
6. 복구 때는 체크포인트 및 현재 V3를 재검증하고, 현재 V4가 **원래값 또는 시험 후보와 정확히 동일할 때만** 원래 상태로 되돌리기.

모듈은 실제 환자 저장소 접근·자동 이전 API를 제공하지 않으며 `productionWriteOccurred:false`를 결과에 고정한다.

## 확인된 장점과 남은 위험

- 기술적으로 체크포인트 우선 기록과 재조회 검증, 실패 후 즉시 원본을 덮어쓰지 않는 **보수적 충돌 처리**를 시험했다.
- **P0·D05/D06:** 메모리 Map은 실제 백업이 아니므로 저장소 손상·기기 교체·브라우저 데이터 삭제·전원 종료 후 복구가 보장되지 않는다. 암호화·키 관리·명시적 백업 파일·실제 복원시험이 남아 있다.
- **P0·D05:** 기존 V4 체험판 스키마가 확장 데이터를 그대로 읽는 운영 모듈이 아니다. UI와 저장소의 정식 이전 기능은 여전히 미구현이다.
- **P1·D06:** 손상된 후보가 남으면 자동 복구를 거부한다. 실제 구현에서 보존된 이전 스냅샷을 사용자가 확인하고 별도 안전 절차로 복구할 경로를 마련해야 한다.
- **NT·D04/D05:** Android/iOS 실기기, 브라우저 탭 강제 종료, 저장 용량과 멀티탭 실제 경쟁 조건 검증이 없다.
- **NT·P01–P06/C01–C02:** 환자 6명과 보호자 2명의 가상 복원 과제 T07 미실시. 사용성 결론은 가설(확인 필요)이다.

S01–S12 암종별 책임전문의 및 M03–M06 공동 돌봄 역할은 실제 참여·승인 자료가 없다. 이번 범위는 암종별 의학 문구가 아닌 공통 데이터 저장 기술이라 치료 콘텐츠 임상 감수는 범위 밖이다. **전체 ApuDa의 100점 평가·의료진 승인·출시 판정은 내리지 않는다.**
