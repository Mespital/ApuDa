# ApuDa 환자 수첩 V3 기록 경로 전수 점검 및 구·신버전 혼재 대응안

- 일자: 2026-11-11 KST
- 검토 방식: **AI 사전점검**. 30인 감수 프레임워크 중 D05(개발·품질), D06(개인정보·보안), D04(접근성), M03(환자 기록 사용성) 관점을 사용. 실제 전문가/환자·보호자 참여·승인 **없음**.
- 코드 버전: `Mespital/ApuDa`, Draft PR #294 (브랜치 `fix/note-v3-restore-integrity-20261110`). GitHub 원격 소스와 부분 로컬 스냅샷을 함께 조사. 실제 환자·Google Drive 데이터는 열람하지 않음.
- 작업 범위: V3 `localStorage` 쓰기, 백업·복원·전체 삭제, 대화·알림 등 보조 기록, Service Worker, 외부 Drive 백업 후킹, V4/IDB 전환 중 구형 탭 혼재. **운영 배포·main 병합 없음.**

## 핵심 결론

**P0 미해결**: 실제 V3는 `localStorage`에 일반 저장·복원·복구·삭제를 직접 수행한다. 두 탭에 대한 기존 진단은 `replace`·`recover` 경로에서 최신 데이터 손실 가능성을 **2/2 재현**했다. PR #294의 IndexedDB 합성 원자성 11/11 Chrome PASS는 기존 V3와 무관하므로 운영 안전성을 입증하지 않는다.

**추가 발견**: `apuda-backup.js`는 `Storage.prototype.setItem`을 교체하여 기본 기록의 쓰기를 감지하고, Drive 자동 백업을 예약한다. 새 백업 업로드 뒤 `prune()`이 호출되어 오래된 사본을 최대 7개 보관 정책에 따라 삭제할 수 있다. 구형 탭이 오래된 데이터를 새로 업로드하면 백업 시계열도 영향을 받을 수 있다는 **소스 기반 위험 가설**이다. 실제 계정에서 재현하지 않았으며 Drive 파일 변경을 수행하지 않았다.

## 전환 설계: 기존 데이터를 절대 덮어쓰지 않는 단계적 출시안

1. **이전 전 증거 보존:** 건강기록 원문, JSON 다운로드, 복원 체크포인트, 대화기록, Drive 백업 목록의 존재와 크기를 별도 확인하되 실사용자 값은 로깅하지 않는다. 새 포맷에 원문 길이·SHA-256·생성 시각·기존 버전만 메타로 저장한다. 사용자가 실제 저장된 파일을 확인하기 전에는 삭제/복원/자동 이전 진행 금지.
2. **혼재 감지:** 구형 `localStorage` 원문이 이전 당시 기록과 달라졌다면 신형 IndexedDB로 자동 덮어쓰거나 백업을 업로드하지 않는다. 읽기 전용 충돌 화면을 보여주고 **구형 원문과 신형 원문을 각각 내보낼 수 있게** 한다. `storage` 이벤트는 힌트일 뿐 원자성 보증이 아니다.
3. **중간 호환 버전:** 기존 V3의 모든 중요 쓰기 경로를 단일 저장 계약으로 옮기고 *이전·이후 해시 대조/복구 기능*을 붙이는 별도 버전이 필요하다. 캐시된 **더 오래된 V3 탭은 새 잠금 규칙을 따르지 않으므로 자동으로 안전해지지 않는다.** 탭 종료 확인과 불일치 탐지, 충돌 UI, 사용자 수동 선택이 필요하다.
4. **Drive 백업 별도 게이트:** 이전 완료 승인 전에는 새 버전의 자동 Drive 업로드와 자동 `prune()`을 재개하지 않는다. 기존 구형 탭의 Drive 동작까지 중앙에서 중단할 수 없다는 한계를 사용자에게 알려야 한다. 실제 Drive 권한·파일을 건드리는 검증은 별도 명시적 승인 후에만 수행한다.
5. **이전 완료 검증:** 동일 원본의 라운드트립(원문 보존), 두 탭 동시 수정, 오래된 탭 재접속·오프라인 SW·다운로드 실패·쿼터 오류·중간 강제 종료·브라우저 저장소 정리, Android/iOS Safari 실기기를 합성 데이터로 테스트한다.

## 혼재 전환 보호 시제품 (합성 데이터만)

- `public-site/note/v3-mixed-version-guard-sandbox.js` — 복수 버전의 기록 사본을 순수 인메모리 문자열로 비교. 예전 탭이 기본 데이터를 바꾸거나 신형 탭이 다른 사본을 수정하면 `manual-review`로 전환하고 **구형 원문·신형 원문 둘 다 손대지 않고 반환**한다. 파일·브라우저 저장소·Drive에는 접근하지 않는다.
- `tools/tests/apuda-note-v3-mixed-version-guard.cjs` — 구형 탭만 수정, 두 버전 동시 수정, 기존 JSON이 손상된 경우까지 원문 분리 보존 및 자동 이전/업로드/Drive 정리 **3가지 모두 거부**를 검증. 합성 테스트 PASS.
- **중요 제한:** 두 원문이 같다는 순간 상태만으로 구형 탭 종료를 확인할 수 없다. 그래서 `snapshot-stable`에서도 자동 이전을 허용하지 않는다. 이는 운영 기능이 아닌 fail-closed(불확실하면 자동 변경 거부) 판단 모델이며 실제 혼재를 해결하지 않는다.
