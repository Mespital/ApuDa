# ApuDa 환자 수첩 V3→V4 구형 탭 차단 사전검사 (합성 데이터 전용)

작성일: 2026-11-12 KST
대상: Draft PR #294 `fix/note-v3-restore-integrity-20261110`
검토 방식: AI 기술 사전점검(D05 개발/품질, D06 개인정보/보안, D04 접근성). 실제 의료진·환자·보호자의 참여나 승인은 없음.

## 목적과 배포 차단 조건

운영 V3의 `localStorage` 저장·복원·삭제가 다중 탭 간 원자성을 보장하지 못하는 P0 위험이 남아 있다. 특히 오래된 탭은 새 IndexedDB 저장 계약 및 수정번호(revision)를 사용하지 않으므로, 신형 탭에 검증 기능을 넣어도 구형 탭의 쓰기를 원격에서 차단할 수 없다. Google Drive 자동 백업·사본 정리(`prune`, 최신 7개 유지)는 구형 탭이 호출할 수 있어 별도 차단·모의 검증이 필요하다.

새 `v3-cutover-fence-sandbox.js`는 **합성 원문 스냅샷**의 `note`, `chat`, `checkpoint`를 서로 비교하는 순수 정책 함수다. 외부 저장소, 실제 데이터, 서버, 네트워크, Drive를 읽거나 수정하지 않는다. 상태를 보고할 때는 값 대신 **변경된 필드 이름**과 차단 사유만 반환한다.

## 판정 조건

검사 입력은 V3 기준 사본과 V4 대상 사본이며, 다음 5개의 조건을 `true`로 명시해야 한다. 하나라도 미확인/오류/불일치면 전환 **차단**이다.

1. 구형 V3 탭 종료 확인 (다른 기기/브라우저까지 완벽한 증명은 불가)
2. 오프라인 Service Worker/캐시 버전 확인
3. 대기 중인 Google Drive 자동 업로드·정리 작업이 없는지 확인
4. 독립 백업 파일의 실제 다운로드·재검증 확인
5. 환자 또는 보호자의 양쪽 분기 비교 및 사용자 승인

또한 양쪽 원문 스냅샷의 note/chat/checkpoint가 기준과 정확히 일치해야 한다. **다섯 조건 모두 참이어도 개발 시제품은 자동 이전, 쓰기, Drive 업로드·정리 권한을 일절 반환하지 않는다.** 운용에 연결되지 않은 독립 모듈에서 허가를 내면 잘못된 안전 확신을 줄 수 있기 때문이다.

## 합성 자동시험

`node tools/tests/apuda-note-v3-cutover-fence.cjs`

- 전체 조건이 `true`여도 미연결 시제품은 차단
- 구형 탭 건강기록 변경, 채팅 변경, 복구 체크포인트 변경
- 신형 기록만 변경, 양쪽 기록 각각 변경
- 구형 탭 종료 미확인, 오프라인 SW 버전 미확인
- Drive 작업 대기, 독립 백업 미확인, 사용자 수동 검토 미완료
- 입력 유효성 실패 및 저장소/네트워크 API 부재 확인

**로컬 Node.js 테스트 결과: 12개 항목 PASS.** 이 결과는 정책 함수의 분기와 테스트 격리만 확인한다. 실제 두 개의 창이나 Android/iOS 모바일 실기기에서의 저장·복구·구형 탭 차단은 **미검증(NT)** 이다.

## 운영 적용 전 추가로 필요한 개발

- 구형 탭 캐시 복귀 감지, 명시적 읽기 전용 전환 또는 사용자 안내 화면
- 각 저장 함수 14개 영역(W01–W14)에 수정번호·충돌 처리 일관 적용
- Drive 자동 백업/`prune` 비활성화 시점 및 이미 켜진 구형 탭의 한계 문서화
- 원본 V3, 채팅, 체크포인트, 실제 백업 목록의 개별 내보내기·확인·복구 절차
- Chrome/Android/iOS Safari 2개 탭에서 합성 데이터 실기기 검증

**절대 금지:** 운영 `main` 병합, Netlify 운영 배포, 실제 환자/논술 기록 읽기·쓰기, Drive 실제 업로드·삭제, 기존 V3 데이터 자동 이전.
