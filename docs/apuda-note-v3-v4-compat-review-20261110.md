- 기준일: 2026-11-10 (한국시간)

- 대상: `public-site/note/note-app.js`, `note-storage.js`, `note-safety.js`, `public-site/note-v4/app.js`, V4 화면 HTML
- 실제 전문의 승인: 없음(이 자료에 해당하는 실제 검토 기록 미제공)

## 이전 설계의 승인 기준(향후)

1. V3 JSON 백업 원본과 검증용 SHA-256 지문을 보존하고, 별도의 새 저장 영역에만 이전 초안을 생성
2. 모든 필드 목록·개수·시각·단위·질문·자유 메모를 **손실 없이** 비교하는 자동 테스트 확보
3. 성공 전에는 V3 운영 키를 절대 덮어쓰지 않고 사용자에게 비교 요약·취소·복원 경로 제공
4. 2개 기기·2개 브라우저의 가상 데이터 시나리오 및 실제 참가자 사용성 검증
5. 마이그레이션 실패·저장 용량 초과·브라우저 종료·중복 실행·같은 날짜 중복 기록에서 원본 보존 확인
6. 실제 의료진 검토가 필요한 표시 문구는 별도 승인받고, 최소한 기술 검증과 환자 시험 전 운영 배포 금지

### 범위 밖 보호

`public-site/nonsul/`의 자녀 논술 기록과 V3 운영 키 `apuda_cancer_care_v1`, Netlify 설정, 실제 구글 드라이브 데이터는 이 변경에서 조회·수정·삭제하지 않음. Netlify 무료 플랜도 변경하지 않음.

## 2026-11-10 추가: 원본 보관 단계(Archival Stage) 구현

- 추가 모듈: `public-site/note-v4/v3-lossless-stage.js` (V4 데모·V3 운영 화면에서 로드하지 않음)
- 추가 테스트: `tools/tests/apuda-note-v3-lossless-stage.cjs`
- 동작: 사용자가 **명시적으로 전달한** V3 JSON이나 유효한 백업 파일 내용을 메모리에서 검증하고, 동일 원문과 SHA-256(위변조 여부를 확인하는 지문)을 묶어 반환. 원본 문서가 문자열이었다면 공백과 줄바꿈까지 정확히 되돌릴 수 있음.
- 원본 유지 대상: 환자 기본 정보, 날짜별 여러 체온, 약, 일정, 혈액검사 단위, 모든 진료 질문·답변, 메모, 추가 정의되지 않은 필드까지 **V3 JSON 안의 전체 자료**. 이후 V4에서 실제로 읽고 표현하는 기능은 아직 구현되지 않음.
- 미포함: V3 JSON과 별도로 저장되는 채팅 기록 `apuda_note_chat_v1`, 실제 구글 드라이브 사본 등. 해당 저장소는 별도로 확인해야 함.
- 차단 정책: 입력 크기 16MiB 초과, 지원하지 않는 JSON·손상 데이터, 지문 불일치, 검사 건수 불일치 시 실패 처리. `readyForV4:false` 고정.
- 보안 주의: SHA-256은 **암호화가 아님**. 준비 단계의 구조에는 환자 정보 원문이 그대로 포함되므로 콘솔·분석 서비스·외부 서버로 전달하거나 자동 저장해서는 안 됨. 현재 어떤 브라우저 저장소에도 이 파일을 자동 저장하지 않으며, 모듈 자체는 라이브 UI에서 실행되지 않음.
- 합성 시험 통과: 원본 JSON 정확히 왕복, 포맷 v1/v2, 체온 37.2→36.8, 질문 4개·메모·미정의 필드 보존, 변조·초과 용량 거절.
- 미시험: 실제 환자 기록, 브라우저 저장 실패와 탭 종료, Android/iOS 메모리 사용량, 환자·보호자 8명 과제, 전문의 승인. **출시 승인을 뜻하지 않음.**
