# ApuDa 환자 수첩 V3 복구 무결성 보호 — 개발 브랜치 검토 기록

작성일: 2026-11-10 (KST) · 상태: **AI 사전 점검 / 개발 전용 / 운영 미반영**

## 1. 재현된 결함과 위험도

- 기존 체크포인트(`apuda.note.checkpoint`, `schemaVersion: 1`)는 `afterHash`(복원 직후 기록 해시)만 보관하고 `before`(복원 이전 기록)의 해시가 없었다.
- 기존 `recover()`는 `before`가 문자열이면 원본의 구조·내용 무결성 검증 없이 저장한 뒤 복원 사본을 지웠다.
- 별도 합성 기록 실험에서 `before`를 `{"broken":true}`로 오염시키자 기존 코드가 성공을 반환하고 사본까지 지우는 동작을 재현했다. **실제 사용자 기록이 손상되었다는 증거는 아니다.**
- AI 위험 분류: P0 후보(수동 복원 시 자료 손상 가능). 실제 발생 빈도와 사용자 영향은 미확인.

## 2. 제안 패치

1. 새 체크포인트 `schemaVersion: 2`에 복원 이전 원본의 `beforeHash`(SHA-256)와 `beforeBytes`, 존재 여부 `beforeExists`, 복원 이후의 `afterHash`와 `afterBytes`를 기록한다.
2. `recover()`는 이전 원본의 바이트 길이 및 SHA-256 일치, 현재 기록의 바이트 길이 및 SHA-256 일치, 작업 직전 체크포인트/기록의 변경 여부를 확인한다.
3. 기록을 기록하거나 삭제한 뒤에도 **read-back verification**(저장 결과 재조회)을 수행한다. 실패하면 체크포인트를 보존한다. 복원 완료가 확인된 후에만 체크포인트를 지운다.
4. 구형 V1 체크포인트는 `checkpoint()` 조회 및 사용자의 원문 JSON 다운로드 경로를 유지하되, 무결성 정보가 없는 V1의 **자동 되돌리기는 차단**한다(`legacy-checkpoint-review-required`).
5. 앱의 사용자 안내 문구에는 V1 자동복원 차단과 사본 수동 검토 필요성을 명시한다. 기존의 복원 승인·기록 내보내기 및 이후 재복원 동작은 유지한다.

## 3. 합성 데이터 자동 검증

- 기존 `tools/tests/apuda-note-storage.cjs`: 유효/무효 백업, 할당량 오류, 경쟁 상태, 기존 undo, SOS 저장 실패 검증.
- 신규 `tools/tests/apuda-note-v3-restore-integrity.cjs`: V2 원본/대상 SHA-256, 기존 기록 부재, 저장 사본 변조 및 같은 바이트 수 변조, 이후 기록 수정, 저장/삭제 무응답, 체크포인트 제거 실패, 체크포인트 저장 실패, V1 fail-closed와 다운로드용 조회, 재차 백업 불러오기.
- 진단 `tools/tests/apuda-note-v4-existing-restore-audit.cjs`: 수정 전 RISK REPRODUCED → 수정 후 RISK NOT REPRODUCED.
- 모든 테스트는 **프로세스 내 가짜 Storage(Map)와 가상의 환자 기록**만 사용한다. 브라우저 사용자 `localStorage`, 서버 데이터, 개인 정보, Netlify 운영 사이트에 접근하지 않는다.

## 5. 승인 전 확인해야 할 제한

- SHA-256은 비의도적 손상을 탐지하는 **무결성 해시**이지 서명·암호화·접근 통제가 아니다. 동일 출처의 악성 스크립트가 원본과 해시를 동시에 변조하는 경우를 방어하지 못한다.
- `localStorage` 다중 키 쓰기는 원자적 트랜잭션이 아니다. 최종 비교로 위험을 줄이지만 창 간 동시 변경을 완전히 배제하지 못한다.
- V1 사본의 자동복원 차단은 기존 사용 동작에 변화가 있다. **원본을 지우지 않고 다운로드 가능하도록 보관**하며, 실제 서비스 반영 전 UI 안내 및 수동 파일 확인 절차를 검증해야 한다.
- 실제 운영 적용 전 브라우저 실측, ApuDa 의료/환자 UX 감수, GitHub 검토·승인 절차를 별도로 거친다.
- 이 문서와 코드는 **draft PR 제안일 뿐이며 `main` 머지, Netlify 운영 배포, 실제 환자 데이터 변경을 허용하지 않는다.**
