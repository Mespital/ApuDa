## 2. 사전검사 의사결정

| 경우 | 결과 | 이유 |
|---|---|---|
| 원본/대상/요약 목록 일치 + 모의 여유 충분 | 가상 사전검사 조건 통과 | 추가 시험 진행만 가능. **운영 허가 아님** |
| V3 원본이 변경됨 | 자동 진행 차단 | 원본 변경 후 오래된 백업 사용 방지 |
| 이전 V4 대상값이 변경됨 | 자동 진행 차단 | 다른 탭·세션이 쓴 값 덮어쓰기 방지 |
| 모의 저장 용량 부족 | 자동 진행 차단 | 체크포인트 우선 보존 |
| 저장 용량 알 수 없음 | 자동 진행 차단 | 용량 보장을 가장하지 않음 |
| Manifest 내용/해시 불일치 | 자동 진행 차단 | 손상된 요약 목록을 신뢰하지 않음 |

저장 공간에 대한 요구량은 `2 × (체크포인트 JSON UTF-8 바이트 + 후보 JSON UTF-8 바이트) + 4,096바이트`로 **안전측 모의 추정**한다. 브라우저 스토리지의 실제 한도나 원자성을 보장하지 않으며, 연결된 저장소 측정·용량 확보 기능이 아니다.

SHA-256은 우발적인 손상 여부를 확인하는 **무결성 해시**다. 공격자가 원문과 해시를 함께 변경하는 경우를 방어하는 인증수단도, 환자 기록의 비밀성을 보장하는 암호화도 아니다. 실사용 백업에는 별도의 기밀성·인증·키 관리 설계가 필요하다.

## 3. 기존 V3 복구 코드에서 확인한 위험

**관찰 위치:** 현재 GitHub `main`의 `public-site/note/note-storage.js`, `recover(storage,key)` 및 `checkpoint(storage,key)`. `main` 파일과 본 개발 환경의 파일이 동일함을 코드 대조로 확인했다.

**합성 데이터 재현:** `node tools/tests/apuda-note-v4-existing-restore-audit.cjs`

1. 가상 저장소에 정상적인 이전 기록과 새 기록을 놓고, 기존 `replace` 함수로 체크포인트를 생성한다.
2. 체크포인트의 `before` 값을 손상된 JSON 문자열로 변경한다.
3. 기존 `recover()`를 호출한다.
4. 함수는 변경된 `before`를 복구값으로 기록하고 `true`를 반환하며, 복구 체크포인트까지 지운다.

**판정:** `checkpoint()`는 `before` 값의 타입만 검사하고 원문 SHA-256과 내용 유효성을 확인하지 않는다. `recover()`는 복원 후 실제 읽기 검증을 하지 않은 채 복구 정보를 삭제한다. **가상 저장 어댑터에서 재현한 데이터 무결성 결함**으로, 운영 기록에 실제 장애가 발생했다는 뜻은 아니다. 중요도는 기록 소실 가능성에 비추어 **P0 검토 대상**이며, 운영 변경을 승인하기 전 별도로 해결해야 한다.

**권고 수정안(미적용):** 기존 V3 복구 기능을 별도의 보호 PR에서 최소 변경으로 보완한다. 복구 전 체크포인트의 원문·형식·길이·독립 해시 유효성을 확인하고, 복원 대상값의 현재 상태를 다시 확인한다. 복원 후 **원문 재조회+해시 검증에 성공한 경우에만** 체크포인트 제거를 허용한다. 기존 체크포인트에 해시가 없는 경우 자동 복구를 중지하고 수동 검증·별도 백업 경로를 제공한다. 삭제 실패/용량 부족/브라우저 중단/동시 탭의 경합을 합성 자료로 시험한다.

## 4. 운영 전환 차단조건 및 검증 계획

| 우선순위 | 차단 항목 | 다음 검증 | 담당 관점 |
|---|---|---|---|
| P0 | V3 손상된 체크포인트의 무검증 복원 및 복구 정보 선삭제 위험 | 별도 보호 패치와 실패 주입 회귀 테스트 | D05·D06 |
| P0 | 실제 사용자 데이터의 안전한 백업/복구 경로 미검증 | 읽기전용 스냅샷, 검증 가능한 백업, 복원 후 바이트 확인 | D05·D06 |
| P1 | 동시 탭·기기에서 읽기-쓰기 경합(원자성) 미검증 | 거래 단위(Transactional) 저장소 설계와 충돌 시험 | D05 |
| P1 | 백업 파일의 암호화·권한·인증·폐기 정책 미정 | 위험분석과 접근통제 설계 | D06 |
| P2 | 사용자가 JSON 백업과 PDF 진료 요약을 혼동할 가능성 | T07 가상자료 기반 과제·이해 확인 | D01·D03·P/C |

`localStorage`의 단순한 두 번 조회는 원자적 트랜잭션이 아니다. 현재 개발 시뮬레이션의 성공을 다중 탭 또는 기기 간 실제 저장 성공으로 해석하지 않는다.

## 5. 리뷰 범위와 승인 상태

- 필수 30자리 감수 체계는 **책임 분장 기준**이다. 이번에는 비임상 저장·복구 기술에 해당하는 D05(개발·품질), D06(개인정보·보안), D04(접근성), D03(쉬운 설명), 사용자 과제 T07만을 AI 관점에서 검토했다.
- S01–S12 각 암종 책임전문의 및 M03–M06의 실제 의료 감수는 **범위 외·미실시**다. 실사용 환자·보호자 8명 시험도 미실시다.

- PR은 **Draft 유지, `main` 병합 금지, `apuda.app` 운영 배포 금지**, 실제 환자·논술 데이터 보존 및 Netlify 무료 요금제 유지.
