# ApuDa 환자 수첩 V3 — 저장 실패 미저장 내용 보존 (Draft PR #294)

기준: 2026-11-12 KST. 범위: `Mespital/ApuDa` Draft PR #294의 개발 미리보기 한정.

## 위험과 개선
기존 V3의 `save()`와 `saveChat()`은 `localStorage` 기록이 충돌하거나 저장되지 않을 때 현재 탭에서 새로 입력한 내용을 `load()`로 덮거나 대화 배열을 다시 읽어 일부 미저장 수정이 화면에서 사라질 수 있었다.

`note-unsaved-draft.js`는 **오직 브라우저 메모리**에서 보존하는 별도 형식(`apuda.note.unsaved-review`)을 제공한다.

1. 쓰기 예외 시 입력을 원문 문자열로 보관하고 두 저장 경로의 추가 쓰기를 중단한다. 사용자에게 지워지지 않는 경고와 수동 다운로드 버튼을 표시한다.
2. 저장 실패한 수정은 사용자 클릭으로만 `ApuDa_저장실패_검토용_YYYY-MM-DD.json` 파일을 요청한다. 다운로드 성공·파일 앱 보관은 자동 확인하지 못하므로 **다운로드 후 메모리 원문을 자동 삭제하지 않는다**.
3. 고의로 일반 백업 형식(`apuda.note.backup`)과 다르게 저장하여 자동 복원으로 실수로 덮어쓸 위험을 줄인다. 원본과 최신 기록을 **사람이 비교한 뒤** 수동으로 복구해야 한다.
4. 메모리 사용 제한: 개별 항목 16MiB, 전체 32MiB, 최대 8개. 초과 시 기존 미저장 내용을 버리지 않고, 신규 스냅샷 미보존 경고를 표시하며 현재 화면의 변경 내용을 자동으로 재로딩하지 않는다.
5. 미저장 항목이 존재하면 **파일 복원·되돌리기·전체 삭제**를 차단하고 페이지 종료 시 경고를 시도한다. 모바일 브라우저에서는 `beforeunload` 경고가 나타나지 않을 수 있다.

## 알려진 미해결 위험
- **P0:** `localStorage`의 비교 후 쓰기(TOCTOU)는 원자적이지 않다. 이전 탭·구형 SW 캐시·별도 Drive 복원이 새로운 저장 보호층을 우회할 수 있다.
- 구형 `apuda-backup.js`의 Google Drive 자동 업로드 및 오래된 백업 정리(`prune`)는 새 임시 보존 모듈로 중단되지 않는다.
- 저장 실패 전에 사용자가 완료하지 않은 입력(예: 제출 전 폼 필드)은 자동으로 모두 수집되지 않는다.
- 메모리만 사용하는 보호여서 페이지 종료/OS의 탭 강제 종료/앱 종료 시 데이터는 사라진다.
- 메모리 보존 파일은 **암호화되지 않은 민감 건강정보**이므로 안전한 저장 위치와 수신 대상 확인이 필요하다.
