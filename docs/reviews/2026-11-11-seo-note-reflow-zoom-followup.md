## 1. 실제 확대·재배치 결과

1363 물리 화면 픽셀의 Chromium 창에서 **브라우저 정상 확대 기능**으로 200%, 400%, 500%를 시험했다. 개발 미리보기의 `window.innerWidth`, `document.documentElement.scrollWidth`, 표시 카드·FAQ·내비게이션의 계산된 크기를 **읽기 전용으로 측정**했다. 아래 CSS px는 브라우저가 보고한 **유효 뷰포트 너비**이며, 실제 모바일 장치가 아니다.

| 검사 | 유효 뷰포트 CSS px | 문서 폭 CSS px | 가로 넘침 | 화면·조작 확인 |
|---|---:|---:|---|---|
| 200% 브라우저 확대 | **681** | **674** | **없음** | 메뉴·FAQ 각 최소 44px; CTA 약 52px 높이, FAQ 첫 항목 키보드 Enter 확장 확인. 긴 안내문과 하단 의료안전·관련링크 확인 |
| 400% 브라우저 확대 | **340** | **337** | **없음** | `.grid`·`.steps` 모두 **301px 단일 열**. FAQ 확장 상태·개인정보 안내 폭 301px, FAQ 요약 높이 72px. 가로 내용 잘림 징후 없음 |
| 500% 브라우저 확대 | **272** | **269** | **없음** | 콘텐츠 단일 열 **약 233.6px**. 주요 구역에 뷰포트 밖으로 나간 박스 없음 |

모바일 상당 폭의 판단: **340px(320px보다 약간 넓음)와 272px(320px보다 좁음) 모두 동일한 720px 이하 1열 미디어 쿼리 구간에서 정상 재배치**되었다. 따라서 320px에서의 가로 오버플로 가능성을 낮추는 강한 근거이나 **정확히 320px로 설정한 실측은 아님**을 명시한다.

### 키보드·가시성 점검

- FAQ 첫 `<summary>`에 키보드 `Enter`를 적용해 `details.open === true`를 확인했다. 200% 확대에서 확장된 질문과 답변, 주황색 가시 초점 테두리를 화면으로 확인했다.
- `본문으로 바로가기` 링크의 초점 및 본문 이동, 상단 메뉴/FAQ 44px 타깃은 SEO-05에서 이미 개발 미리보기로 확인한 사실을 유지한다.
- `lang="ko"`, `<main>`, `<nav>`, H1·H2·H3, `<details>` 등 의미 구조는 그대로 유지된다.
- 시험 뒤 Chrome 화면 확대를 **100%로 복원**했다.

## 2. 판정·잔여 과제

| 구분 | 판정 | 근거/제한 |
|---|---|---|
| 브라우저 확대 200% | **PASS — 시험 범위** | DOM 가로 넘침 없음, FAQ Enter 작동과 주요 CTA·하단 설명 화면 확인 |
| 브라우저 400%·500% Reflow | **PASS — 시험 범위** | 유효 340px·272px에서 한 열 배치, 가로 넘침 0 |
| 정확히 320 CSS px | **NT** | 340/272px 두 측정으로 근접 검증했으나 정확한 320px 프리셋은 제공되지 않음 |
| Android/iOS 실기기·터치 | **NT** | 실제 기기·손가락·주소창 변화·OS 글자 크기 변경 미시험 |
| TalkBack / VoiceOver | **NT** | 접근성 트리만으로 실제 낭독 순서·발음·모바일 초점을 합격 처리할 수 없음 |
| 실제 환자·보호자 이해 과제 | **NT** | 참여자 0명, 가상 시나리오 성공률 산출 불가 |
| 임상·개인정보 감사 | **범위 외/승인 대기** | 실사용 노트 저장·백업·복원·개인 기록을 다루지 않음 |

**신규 P0/P1/P2 결함은 이 테스트 범위에서 확인되지 않았다.** 미시험 항목이 남아 있으므로 WCAG 2.2 전체 적합성, 서비스 전체 100점 합격, 전문의 승인 또는 사용자 검증을 선언하지 않는다.
