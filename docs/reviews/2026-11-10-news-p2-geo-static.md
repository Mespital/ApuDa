# ApuDa 뉴스 GEO-01: 정적 HTML 요약 개발 검증

검토일: 2026-11-10 (Asia/Seoul)

브랜치: `feat/apuda-seo-geo-marketing-skills-20261110`, Draft PR #291

상태: **개발 전용 / 운영 배포·main 병합·VPS 실행 없음**

## 문제와 접근

현재 `/news/`는 최초 HTML에 `불러오는 중`이 표시되고 JavaScript가 최신 JSON을 가져와야 본문이 만들어진다. 이는 일부 AI 검색/일반 크롤러에서 핵심 기사·보고일·출처 탐색을 어렵게 할 수 있는 **잠재적** GEO(Generative Engine Optimization, 생성형 검색 접근성) 위험이다. 실제 Google/Naver 색인 실패는 확인되지 않았다.

### 설계

1. 기존 동적 뉴스 UI **그대로 유지**.
2. 초기 HTML에 `staticNewsSnapshot`을 추가하고 현재 최신 JSON의 `report_date`, TOP에서 선별된 **기사 제목 및 원문 링크**만 출력. 기사 본문·이미지·AI 작성 의학적 판단은 복제하지 않음.
3. 페이지는 JavaScript가 꺼져도 마지막 공개 보고일과 링크를 표시한다. JS가 정상적으로 브리핑 JSON을 렌더링하면 정적 블록을 숨겨 **중복 표시를 방지**한다. 데이터 로딩 실패 시 정적 내용은 그대로 보존한다.
4. `build_static_briefing.py`는 기존 `index.html`의 명시된 주석 마커 두 개 사이만 변경. 마커 없거나 날짜·경로 형식이 맞지 않으면 실패 후 파일 불변. 매체 URL은 허용된 4개 출처의 HTTPS 호스트만 허용하고 제목·URL·출처 문자를 HTML escape 처리.
5. 차후 **운영 배포가 별도로 허용된 이후** 매일 발행하는 스크립트에서 데이터 파일을 반영한 다음 매번 최신 `main`의 HTML을 기준으로 정적 요약을 다시 생성한다. 이로써 다른 작업자의 HTML 수정과 경합할 때 오래된 페이지 전체를 덮어쓰지 않도록 했다.

## 현재 개발 데이터 출력

- `latest.json` 보고일: **2026-11-01** (11월 10일 기준 9일 경과).
- 최초 HTML의 정적 요약에도 **2026-11-01** 날짜를 명시하므로 최신이라고 오인시키지 않는다.
- 기존 11월 1일 TOP 5건에서 명백한 행사·부고·홍보 행사를 제외하고 **공식 허용 매체 원문 링크 2건**만 표시(기사의 임상 중요도 자체를 보증하지 않음).
- 기존 일별 JSON, FAQ 3,000문항, 환자·논술 기록, Netlify 설정 수정 없음.

## 보안 및 변경 범위

- 출처 URL은 `dailypharm.com`, `bosa.co.kr`, `medipana.com`, `kpanews.co.kr` 및 해당 하위 도메인의 HTTPS만 허용. `javascript:` URL 또는 타 사이트 URL은 삽입하지 않는다.
- 기사 제목은 `html.escape()` 처리하여 크로스 사이트 스크립팅(XSS, 콘텐츠 삽입형 공격)을 방지한다.
- 보고일 데이터 경로 `/news/data/YYYY-MM-DD.json`만 읽으며 경로 탐색(`../`) 차단.
- 생성기는 네트워크 요청, 인증키 읽기, 환자 기록 접근, 외부 발행을 수행하지 않는다.
- 동기화 경합 방지를 위해 `publish.sh`는 데이터 파일을 복원한 **후** 가장 최신 저장소 HTML에서 요약을 갱신한다. 이번에는 `publish.sh`를 **실행하지 않았다**.
- 기존 자동 발행의 9일 지연 원인·실제 수집 성공 여부는 별도 VPS 로그 진단이 필요하다.

## 완료 정의와 한계

완료된 것은 **검색에서 읽을 수 있는 정적 자료의 개발 구현과 회귀 테스트**다. 검색 노출·추천·순위 개선이나 기사 의학적 정확성을 의미하지 않는다. 출처 자료의 시차가 크므로 정적 내용도 역사적 스냅샷으로만 취급한다. 실제 배포는 승인 전까지 하지 않는다.
