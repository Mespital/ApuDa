# ApuDa 환자 수첩 V3→V4 이전·취소·되돌리기 모의시험

- 기준일: 2026-11-10 (Asia/Seoul)
- 구현: `public-site/note-v4/v4-migration-rehearsal.js`
- 테스트: `tools/tests/apuda-note-v4-migration-rehearsal.cjs`, `apuda-note-v4-extended-a11y-static.cjs`
- 검토: **AI 기술 사전점검**, 실제 30인 전문가/사용자 참여 없음
- 상태: **합성 자료를 메모리에 올린 모의시험만 통과. 실제 백업·저장·복원·배포 아님**

## 핵심 결정

현행 V3 기록을 V4에 자동 이전하지 않는다. 우선 원문 그대로의 V3와 이전 대상 V4의 **이전 상태(원본 스냅샷, Snapshot)** 를 보존하면서, 새로운 V4 확장 모델 초안이 어떻게 만들어지고 취소·복귀할지를 브라우저 저장소에 쓰지 않고 실험한다.

| 단계 | 함수 | 실제 동작과 제한 |
|---|---|---|
| ① 준비 | `prepare(v3Raw, previousV4Raw)` | 직접 전달한 두 문자열(이전 대상 없음은 `null`)의 원문·UTF-8 크기·SHA-256 저장, V3 유효성 검사, V4 확장 초안 생성 |
| ② 검증 | `verify(plan)` | 원본/이전 대상/초안의 지문과 건수 재검사. 변조 시 차단 |
| ③ 모의 이전 | `simulateForward(plan, currentV3, currentV4)` | 현재 상태가 준비 시점과 완전히 동일할 때만 **반환 객체** 안에 새 V4 값 표시. 저장하지 않음 |
| ④ 취소 | `simulateCancel(plan, currentV3, currentV4)` | 현재 상태가 이전 상태와 동일할 때 그 문자열을 그대로 반환 |
| ⑤ 모의 되돌리기 | `simulateRollback(plan, currentV3, candidateV4)` | 모의 이전 후 두 값이 예상대로일 때 기존 V4의 원본 문자열 또는 `null` 그대로 반환 |

모든 결과는 `readyForProduction:false`, `canWriteToV4:false`의 비운영 체계를 따른다. 파일 읽기·`localStorage`/`sessionStorage`·IndexedDB·서버 호출·자동 동기화·실제 사용자 기록 접근 코드가 없다. 사용자가 명시적 입력을 전달하지 않으면 동작할 수 없다.

**주의:** 이 모듈이 메모리에 잡아두는 스냅샷은 영구 백업이 아니다. 브라우저 탭이나 기기가 종료되면 사라질 수 있다. SHA-256은 암호화가 아니고, 실제 건강정보를 이렇게 여러 사본으로 다루는 방식에는 별도 보안·메모리 평가가 필요하다. 모의 대상은 **가상 자료만** 사용한다.

## 자동 검사 증거

- 원래 V3 JSON의 공백·줄바꿈·한글·이모지까지 **정확한 원문 보존**.
- 같은 날짜 복수 로그, 두 시각 체온 37.2℃/36.8℃, 질문 4개·답변·우선순위, 빈 통증/식사 0, 단위 미상, 미정의 필드 유지.
- 모의 이전 후 V3 원문 불변, 되돌리기 후 기존 V4 원문 공백까지 정확히 복귀.
- 기존 V4가 `null`(키 부재)인 경우와 `''`(빈 문자열인 키)를 구별해서 복귀.
- 중간에 V3 또는 V4 내용이 바뀐 경우 모의 이전·취소·되돌리기를 모두 **중단(충돌 감지)**.
- 원본, 대상, 후보 또는 건수를 일부 수정한 경우 `verify()` 실패. 비운영 상태를 조작해도 거절.
- 지원하지 않는 V3/손상 JSON, 직접 전달하지 않은 기존 대상, 최대 크기 초과 입력을 거절.
- 실제 V3·기존 V4 체험·자녀 논술 앱에는 모듈을 로드하지 않음.

검사 명령:

```bash
node tools/tests/apuda-note-v4-migration-rehearsal.cjs
node tools/tests/apuda-note-v4-extended-a11y-static.cjs
```

나머지 기존 검사 6종(확장 UI·확장 모델·필드 대조·원본 보관·기존 미리보기·V3/V4 계약)도 다시 통과했다.

## 접근성·모바일 현황

HTML의 한국어 언어값·건너뛰기 링크·상태 알림·버튼 텍스트와 CSS의 48px 주요 버튼, 키보드 초점 표시, 360/680px 규칙, 모션 감소 설정을 정적 검사했다. 주요 텍스트 색 조합 **6개 대비비(Contrast ratio)가 모두 4.5:1 이상**이었다. 이는 특정 색 쌍의 계산 결과이지 WCAG 적합성 인증이 아니다.

- 준비된 브라우저 시험: `tools/tests/apuda-note-v4-extended-browser.cjs`
- 실행: `APUDA_BROWSER_TEST=1 node tools/tests/apuda-note-v4-extended-browser.cjs` (Playwright Chromium 사용 가능 환경에서만)
- 내용: 가상 데이터에 한해 320px 및 390px/글자 200% 화면, 넘침, 정보 표시, 저장소 마커 불변, 외부 요청 부재 확인.
- 현재 컨테이너는 Chromium 프로세스 소켓 권한 제약이 있어 **실제 브라우저 시험 미실시(NT)**. 코드만 작성한 것은 실브라우저 시험 통과와 다르다.
- 실기기 Android/iOS, 키보드 순회, VoiceOver/TalkBack, 8명 사용성 시험은 NT.

## ApuDa 30역할 감수 기준과 출시 차단

| 번호 | 상태·근거 | 책임 관점 | 우선순위 |
|---|---|---|---|
| R01 | 실제 영구 백업/다른 저장소와 묶은 복원은 **미구현** | D05·D06 | **P0** |
| R02 | 기존 V4 생산 스키마는 V3 전체 기록을 수용하지 못함 | D05·M03·M04 | **P0** |
| R03 | 원본과 대상의 충돌 탐지·변조 탐지는 **합성 메모리 시험 통과** | D05·D06 | 개발 범위 검증 |
| R04 | 검사 단위·작성자·예정 일정 문구는 실제 간호/약사 검증 없음 | M03·M04 | P1/실제 검토 대기 |
| R05 | 실제 Android/iOS 접근성·대용량·멀티탭 충돌·저장 실패 재현 없음 | D03·D04·D05·D06 | NT |
| R06 | 실제 환자 6명·보호자 2명 T05–T08 미실시 | P01–P06·C01–C02 | NT |

S01–S12(12개 암종별 책임전문의)는 공통 데이터 마이그레이션 모의시험에 대해 암종별 임상 자료 검토 **범위 밖**, 실제 참여·승인 없음. M05·M06은 관련 콘텐츠 변경이 없어 실질 점검 범위 밖. 전체 앱의 100점 점수·전문의 승인 여부를 산출하지 않는다.

## 실제 저장 기능 개발에 앞서 필요한 별도 조건

1. 실제 V3 수첩과 **본문 외 자료**(`apuda_note_chat_v1`, 글꼴 선택, 구글 드라이브 사본 등)의 이전 포함 범위 및 사용자 동의 확정.
2. 읽기 전용 완전 백업(원본 JSON과 SHA-256, 필요한 별도 저장소별 체크섬), 외부 복구본과 사용자 확인 절차 설계.
3. **새로운 이름의 V4 저장소**만 사용하고, V3 운영 키를 덮어쓰지 않으며 완료 후에도 원본 V3 접근 경로 유지.
4. 쓰기 전후 원문·지문 검사, 실패/용량 초과/동시 탭/기기 종료 시 되돌리기, 사용자 취소, 버전 충돌 처리.
5. 실제 저장소를 사용하더라도 개인정보 분리·암호화·접근권한·삭제/수명 정책 검토와 실기기 및 실제 사용성 시험을 먼저 진행.
6. 운영 병합·배포에 대한 명시적 최종 승인. 현재는 별도 개발 브랜치만 허용.

`main`, Netlify 무료 요금제, V3 운영 기록, 자녀 논술 기록은 변경하지 않는다.

## 후속 진척: 격리된 체크포인트·장애 주입 모의시험

`public-site/note-v4/v4-sandbox-checkpoint.js` 및 `tools/tests/apuda-note-v4-sandbox-checkpoint.cjs`를 별도로 추가했다. 직접 전달한 합성 기록을 `new Map()` 기반 **메모리 내부**에만 넣고, 원본 V4 스냅샷·체크포인트 저장·재조회·후보 저장·재조회·원복의 순서를 시험한다. 용량 초과, 첫/두 번째 쓰기 실패, 읽기 결과 손상, 후보 기록 직후 중단, 복구 쓰기 실패, V3/V4 동시 수정으로 인한 충돌까지 재현했다. 대상이 손상되거나 제3자가 변경한 것으로 나타나면 자동 덮어쓰기를 차단한다. 실제 스토리지·영구 백업에 연결되지 않았으므로 **P0 출시 차단은 여전히 유지**된다. 세부 보고서: `docs/apuda-note-v4-sandbox-checkpoint-20261110.md`.
