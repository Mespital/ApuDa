# ApuDa 환자 수첩 V4 | 복구 안전성 가상 시험실

작성일: 2026-11-10 (KST)  
범위: **개발용 브랜치 및 PR #292의 배포 미리보기 한정**  
운영 서비스(`apuda.app`), 실제 환자·보호자 기록, 자녀 논술 기록: **접근하거나 수정하지 않음**

## 목적과 경계

- V3 → V4 변환 과정에서 쓰기 실패·중단·동시 수정·손상이 발생했을 때, 검증된 체크포인트(Checkpoint: 복구용 원본 스냅샷)를 먼저 준비하는지 검증한다.
- 격리된 `new Map()`의 가상 값만 이용한다. 로컬스토리지(LocalStorage), IndexedDB, 업로드 파일, 로그인 API, 외부 네트워크에 대한 읽기·쓰기 경로가 없다.
- 기록 1일, 질문 4개, 복수 체온 측정치(37.2 / 36.8℃) 등을 포함한 **고정 합성 데이터**만 사용한다.
- 브라우저 화면은 `note-v4/rollback-lab.html`. `robots=noindex` 및 콘텐츠 보안 정책(CSP)으로 검색 노출과 연결 시도를 제한한다.

## 시나리오 및 판정 기준

| ID | 가정한 상황 | 기대 결과 | 안전성 이유 |
|---|---|---|---|
| `normal` | 후보값 정상 저장 → 원복 | 복원됨 | 이전 V4 대상값과 V3 원본 보존 |
| `interruption` | 후보값 직후 앱 중단 | 복원됨 | 체크포인트로 중단 지점에서 회복 |
| `candidate-failure` | 두 번째 쓰기 실패 | 복원됨 | 가상 후보 실패 시 원래 대상값 유지 |
| `quota` | 체크포인트 저장 공간 부족 | 사전 차단 | 안전한 복구 정보 없이 변경 시작하지 않음 |
| `concurrent` | 다른 탭의 동시 수정 | 수동 확인 필요 | 자동 롤백으로 제3자 수정값 덮어쓰기 금지 |
| `corruption` | 후보 저장 후 읽어본 값 손상 | 수동 확인 필요 | 미확인 데이터를 자동으로 덮어쓰지 않음 |

모든 시나리오에 공통으로 **실제 쓰기 0회**, **V3 원본 불변**, **질문 4개 누락 없음**을 검증한다. `concurrent`와 `corruption`은 자동 복구 성공이 아니라 **보호 차단 성공**이다.

## 재현 방법

1. 개발 미리보기 페이지의 드롭다운에서 시나리오를 선택한다.
2. **가상 복구 시험 실행**을 눌러 단계별 결과와 보존 지표를 확인한다.
3. 다른 시나리오로 반복한다. 매 실행마다 새로운 메모리 `Map`이 생성된다.
4. 자동화 회귀 테스트: `node tools/tests/apuda-note-v4-rollback-lab.cjs`

## 남아 있는 운영 전환 차단조건 (P0)

- 실제 사용자 데이터를 대상으로 하는 V3 백업·복구·마이그레이션 기능은 **구현되지 않았다**.
- 여러 브라우저·기기·동시 세션에서의 실제 저장소 원자성(Atomicity: 중간 상태 없이 한 번에 적용됨), 복구 재시도와 용량 임계값은 별도 설계/검증이 필요하다.
- 환자 정보 보호와 접근통제, 보안·개인정보 검토 및 실제 사용자·담당 전문가 승인이 필요하다.
- 사용자 논술 기록의 독립 저장소를 포함한 전체 서비스 회귀 테스트와 운영 전환 승인 전까지 `main` 병합, 프로덕션 배포, 환자 데이터 연결을 금지한다.
