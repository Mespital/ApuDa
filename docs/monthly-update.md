# ApuDa 월간 정보 갱신 체크리스트

매달 1일 자동 실행(예약 작업 「ApuDa 월간 정보 갱신」)이 이 문서를 기준으로 사이트의 **시간이 지나면 바뀌는 정보**를 점검·갱신한다.
결과 보고는 `docs/monthly-updates/YYYY-MM.md`에 남긴다.

## 원칙

1. 공식·1차 출처만 근거로 쓴다: 보건복지부(mohw.go.kr), 국민건강보험공단(nhis.or.kr), 건강보험심사평가원(hira.or.kr), 국가암지식정보센터(cancer.go.kr), 국립암센터, 정책브리핑(korea.kr), 보건소·지자체 공식 페이지, 각 단체 공식 홈페이지, 식약처(mfds.go.kr), 주요 의학 언론 보도(보도자료 인용 기사).
2. **페이지를 실제로 열어(fetch) 숫자를 확인한 경우에만** 바꾼다. 검색 요약·블로그만으로는 바꾸지 않고 보고서의 「확인 필요」에 적는다.
3. 의학적 판단·치료 권고 문장은 새로 쓰지 않는다. 숫자·날짜·대상·연락처·제도 이름·급여 여부만 고친다.
4. 금지 표현: '반드시', 완치·효과 보장, 상품명(성분명 사용). 공식 [안내] 문구는 지우지 않는다.
5. 바꾼 곳마다 화면의 '확인 시점' 표기(예: 2026년 10월 확인)를 이번 달로 갱신한다.
6. 바뀐 게 없으면 파일은 건드리지 않고 보고서만 남긴다.

### B. 항암요법·약 정보 — `public-site/assets/apuda-regimens.js`, `public-site/library/regimens/`, `public-site/library/drugs/`
- 국내 허가·급여 변경(새 급여 적용일, 급여 확대) — 심평원 약제 급여 고시, 식약처 허가, 보도자료.
- 바꾼 뒤 `node public-site/tools/test-regimens.js` 실행 → 전부 통과해야 커밋.
- NOTICE_FULL의 '작성 시점(YYYY년 MM월)' 갱신.

### C. 암종별 FAQ 100 — `public-site/library/faq/data/*.json`
- 시간에 민감한 문항만 점검: 국가검진 기준(보통 50번대), 치료비·제도(90번대), 예방접종(94번 전후), 신약·급여가 나오는 문항.
- 답변 문장 구조는 유지하고 바뀐 숫자·날짜만 고친다. JSON 유효성 확인.

### D. 첫 30일 책 미리보기·PDF — `public-site/library/mini/`
- PDF는 자동으로 고치지 않는다. 책 속 수치(급여 시작일, 가이드라인 판, NCCN 버전 등)가 바뀌었으면 보고서의 「책 개정 필요」에 권·쪽·내용을 적는다.

### E. 암환자 노트 — `public-site/note/`
- 앱 안의 제도·연락처 문구가 A와 같은지 확인. 코드 변경 시 `note/sw.js`의 캐시 버전을 올린다.

## 보고서 형식 (`docs/monthly-updates/YYYY-MM.md`)
1. 요약(바꾼 항목 수, 확인 필요 수)
2. 바꾼 것: 파일 · 항목 · 이전 → 이후 · 출처 URL
3. 확인 필요(공식 확인 못 함): 항목 · 이유 · 참고 URL
4. 책 개정 필요
5. 다음 달 미리 볼 일정(예: 8월 상한액 확정, 8월 다음 해 중위소득 발표, 1월 새 기준 적용)
