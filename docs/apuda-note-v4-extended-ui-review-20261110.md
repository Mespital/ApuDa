# ApuDa V4 확장 읽기 전용 화면 — AI 기술 사전점검

- 기준일: **2026-11-10 (Asia/Seoul)**
- 대상: `public-site/note-v4/extended-preview.html`, `extended-preview.css`, `extended-preview.js`, `v4-extended-draft.js`
- 시나리오: **합성(가상) 환자 기록만** 사용. 기존 V3 수첩, 기존 V4 체험판, 운영 사이트, 실사용자 브라우저 저장소 비접근
- 방법: HTML/CSS/JS 소스 점검 + Node.js VM 가상 DOM 자동 검사 + 기존 모델·원본 보존 검사 재실행
- 검토 모드: **AI 사전점검**. 실제 30명 참여·전문의 승인·환자/보호자 시험은 모두 **미실시/미확인**
- 배포 결정: **별도 개발 브랜치에만 보관**, 운영 병합 및 Netlify 배포 불가

## 핵심 결과

V3 원본 손실 없이 표현하는 V4 확장 **읽기 전용 합성 데이터 화면**을 추가했다. 2026-11-10 같은 날짜의 기록 2건과 전날 1건(총 3건)이 각각 나타나고, 진료 질문 4개 전체·답변·우선순위, 여러 측정 체온(36.8℃ 마지막 입력 / 37.2℃ 최고), 통증·식사량 `0`과 빈칸, 작성자 미확인, 검사 단위 `unknown`, 미정의 원본 필드를 모두 렌더링하는 테스트가 통과했다.

**환자에게 공개하거나 실제 기록을 불러오는 단계는 아니다.** 운영 저장소 접근, 환자 파일 선택, 클라우드 송수신, 저장 버튼, 치료 해석 및 자동 이전 기능을 넣지 않았다.

### 30개 감수 역할의 상태

- **S01–S12 (유방·폐·위·대장·갑상선·신장·전립선·췌장·담도·간·림프종·자궁경부):** 이번 화면에는 암종별 치료 문구·진단 해석이 없어 개별 임상 콘텐츠 판정은 **범위 밖**. 책임전문의 12개 포지션의 실제 검토·승인 자료 없음. 합성 프로필의 ‘유방암’은 의학 감수가 아니라 화면 테스트용 문자열이다.
- **M03 간호·M04 약학·M05 심리사회·M06 제도/지원:** 데이터 표시 맥락의 AI 점검 관점 적용(M03·M04). M05·M06의 실제 검토/참여는 없음.
- **D01–D06 설계·개발·보안:** 소스 기반 구조/기술 점검. 특히 D03/D04(시인성·접근성)는 코드 기반 후보만 확인, 실제 사용성 통과가 아님.
- **P01–P06 환자 + C01–C02 보호자:** 실제 8명 참가 **0명/미실시**. ‘같은 날짜 중복·질문 4개·체온 최고값을 도움 없이 이해하는가’는 **사용성 가설(확인 필요)**이다.

전체 ApuDa 제품의 100점 평가 및 임상 승인 판정은 **산출하지 않는다**. 필수 실기기·실제 참여 검증이 NT이기 때문이다.

## 운영 이전의 별도 승인 조건

1. 320px/200% 확대, 키보드, 화면낭독기 및 Android/iOS 실제 사용자 흐름 테스트.
2. V3 원본과 별도 저장소 자료(수첩 대화 등)의 범위 확인; 사용자의 명시적 백업·이전 동의.
3. 기록별 1:1 보존 검사, 실패 시 원본 그대로 되돌리기(rollback), 권한·암호화·저장 용량 점검.
4. 실제 간호·약학 검토와 환자 6명·보호자 2명 과제 시험. 12암종 치료 문구를 나중에 추가한다면 암종별 실제 책임전문의의 별도 감수가 필요.
5. 운영 배포 전 사용자 승인. **현재는 배포하지 않는다.**
