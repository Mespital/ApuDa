## 2. 새 데이터의 보호

- 새 독립 보관소: IndexedDB \`apuda-memory-secure-v3\`. 기존 \`localStorage\`와 분리.
- 보관 내용: \`apuda-memory-v3-data\` 형식의 프로필/일지, 최대 12 프로필·1,000 기록.
- 디스크 보관 형식: **AES-256-GCM(128비트 인증 태그)**, 매 저장마다 무작위 96비트 IV.
- 비밀번호 기반 키 유도: **PBKDF2-HMAC-SHA256 600,000회**, 무작위 128비트 salt.
- 기록과 프로필 별칭은 암호문 내부에만 저장. 평문 비밀번호 서버 전송/기기 보관 없음.
- 여러 탭: 암호화 처리 이후 IndexedDB 단일 \`readwrite\` 트랜잭션 내 **Revision 기반 Compare-and-swap(버전 일치 검사)**으로 충돌을 감지하면 덮어쓰지 않고 거부.
- 대상자별 조회·수정·삭제·진료 요약에서 대상 ID 필수. 기록은 프로필 ID로 구분.
- 보관함이 열려 있는 동안의 화면, 클립보드, 브라우저 악성 확장, XSS 위험은 암호화만으로 사라지지 않음.
- 실서비스 고객계정/클라우드 동기화, 별도 기기 백업 복원, 비밀번호 분실 복구, 실제 옛 기록 가져오기는 **미구현·보류**.

## 4. 사용자 안내·출시 조건

- 사용자는 링크를 열고 먼저 암호화 보관함을 생성한 뒤 대상자별 일지를 사용할 수 있다.
- 한 기기의 한 브라우저에서만 기록이 보인다. 사생활 보호 모드·공용기기에서 실제 환자기록을 입력하지 않는다.
- 중요한 의료기록의 단일 보관 수단으로 사용하지 않는다. 암호 분실·브라우저 데이터 삭제 시 복구되지 않을 수 있다.
- 기존 앱 기록은 기존 \`/memory/#care-diary\`에 그대로 남으며, 새 앱으로 자동 이동하지 않는다.
- 실제 환자·보호자의 사용, 정식 공개, 기존 자료 이전은 독립 보안·모바일 실기기·개인정보 위험 검토 이후 승인 받아야 한다.
