## 2. 30인단 근거와 문제 재평가

가상 사용자 30명 중 특히 다음 4명 관점에서 P0 개선을 우선했다.

- C07(가상 공용 태블릿 사용 보호자), A25(가상 공용 PC 사용자): 브라우저 localStorage 평문·JSON/TXT/복사·PDF의 비암호화 노출 경계.
- C08(부모 두 분을 돌보는 가상 보호자), H29(가상 방문돌봄 서비스 종사자): 한 브라우저 기록을 2명 이상 사용하면 현재 모든 메모가 하나의 7/30일 요약으로 합쳐질 수 있음.

30명은 실제 참여자가 아니며, 성공률·인간의 주관적 반응을 측정한 결과가 아니다. 관련 위험은 공개 UI 코드와 저장소 키 구조로 판단했다.

## 3. 프로필 분리 설계(P0 R02)

**명시적 스코프(Explicit Profile Scope):** 모든 단일 대상 기록 조회·수정·삭제 함수는 프로필 ID가 반드시 필요하고, ID 누락·존재하지 않는 ID·다른 프로필 기록 접근을 거부한다. 전체 기록을 반환하는 공개 API는 제공하지 않는다.

**가명(Pseudonym) 기본값:** 새 프로필은 안전한 Web Crypto의 UUID v4를 사용하고 라벨은 '돌봄 대상 1', '돌봄 대상 2' 순으로만 생성한다. 실명, 생년월일, 주민번호, 진단명을 프로필 키에 넣지 않는다. 이는 UI 단의 혼동 방지 장치이지 완전한 익명화는 아니다.

**현재 20건 상한 유지:** 순수 모듈에서도 전체 레코드가 20건을 넘으면 추가를 차단한다. 환자당 20건 또는 무제한 장기 보관을 제공한다고 주장하지 않는다.

**기존 기록(Migration) 유예:** 기존 V1/V2 JSON을 입력받는 계획 함수는 읽기 전용으로 후보·ID 충돌·한도만 검토하며, 무소속(unassigned) 데이터로 취급한다. 자동으로 특정 프로필에 할당하거나 localStorage를 읽고 쓰지 않는다. 수동 분류·사용자 확인 및 롤백 구현은 후속 단계다.

**건수와 내용 일치:** record의 필드 스키마/날짜/관찰 선택값/메모 1,000자/질문 300자 검증, 중복 ID와 알 수 없는 필드 거부, 사본 반환(원본 변경 방지)을 확인했다.

**알려진 한계:** 2개 대상자에 대해 완전히 다른 계정/보안 경계를 만들지는 않는다. 동일 브라우저 프로필 사용자와 스크립트는 여전히 모든 평문 기록을 읽을 수 있으므로 개인정보 보호 대책이 별도로 필요하다.

## 4. 개인정보 위험(P0 R01) — 현 단계 완화와 향후 필수 정책

| 위협 | 현재 확정된 한계 | 이번 단계 조치 | 후속 출시 전 요구 |
|---|---|---|---|
| 공유 기기·브라우저 프로필 | localStorage 평문 | 기록 입력/요약 앞에 대상자 혼합 주의, 기존 비암호화 경고 유지 | 개인정보 보호 동의·접근 제어 및 기기 잠금 안내, 보관 정책 |
| 비암호화 JSON/TXT 다운로드 | 기존 UI는 암호화 파일 아님 | 기존 기능을 '암호화 완료'라 표시하지 않음 | 8단계 AES-GCM 모듈의 실제 모바일 성능·보안 전문가 검토·암호 분실 UX |
| 클립보드·인쇄물 | 복사한 건강정보가 외부에 남음 | 기존 수신자 주의/인쇄물 경고 유지 | 클립보드·PDF 저장 경로와 자동삭제 가능 범위 고지 |
| XSS/악성 확장 프로그램 | 화면 내 JS가 로컬 데이터를 읽을 수 있음 | 신규 저장 권한/서버 연동 없음 | CSP(Content Security Policy), 의존 스크립트 점검, 공격 모델 |
| 다중 대상 혼합 | 1개 key와 전체 요약 | 현재 미지원 사실 명시, 격리 함수 개발 | 프로필 선택을 모든 기록/요약/검색/백업에 강제 |
| 오작동/데이터 손실 | localStorage와 미검증 IndexedDB 이전 | 자동 기록 이전 없음 | 무손실·실브라우저 트랜잭션/충돌/롤백 재시험 |

**중요:** 프로필 분리는 개인정보의 암호화 또는 사용자 인증을 대신하지 않는다. 로컬 기기 탈취·확장 프로그램·백업 파일 전송에 대한 별도 위험은 남아 있다.

## 5. 재현 가능한 QA

코드 테스트: \`tests/memory/test_profile_scope.mjs\`.

**가상 2개 프로필에 대한 로직/자동검사 PASS** (JS 코드 평가 및 회귀 스크립트):
1. 보안용 UUID 입력 검증, 가명 순번 부여
2. A 조회 결과에서 B 메모 0건, B 조회에서 A 메모 0건
3. A 프로필 권한으로 B 수정·삭제 시 명시적인 예외
4. 동일 ID 신규 추가 차단
5. 업데이트 후 기존 상태 및 다른 대상 내용 변경 없음
6. 조회 결과 수정이 원본 볼트에 영향을 주지 않음
7. 엄격한 날짜·필드·관찰 선택값 검사
8. 전체 20건 초과 차단
9. 기존 JSON V1/V2 검토는 미분류·읽기전용, 자동 이전 없음
10. 기존 JSON 원본·볼트 원본 객체 불변

기존 Memory 배포 판정 스크립트에서도 **PASS: release manifest integrity and live-page isolation / RELEASE: NO_GO / BLOCKING ITEMS: 13 / 15**, \`--require-go\`는 exit code 2. 실제 모바일/브라우저 접근성, 보안 침투시험, 실제 사용자/임상 전문가 감수는 **NT(Not Tested)**.
