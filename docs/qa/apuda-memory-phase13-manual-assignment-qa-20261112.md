## 1. 가상 30인단 리뷰와 연결된 목적

이전 가상 30인단 리뷰의 R02(P0, 두 명 이상의 돌봄 대상 기록이 혼합될 가능성), R03(P1, 기존 저장 방식의 동시 수정 문제), R01(P0, 로컬 평문 저장)에 대한 순차적 완화 중 **R02의 수동 배정·되돌리기 시나리오**를 구체화했다.

가상 사용자 대표 시나리오:
- C08(부모 두 분을 돌보는 보호자): 기록 소속을 확신하기 전 무소속 상태로 보존하고, 내용 검토 뒤 A/B 중 하나에 배정.
- H29(방문 돌봄 종사자): A의 진료 요약에 B의 메모가 들어가지 않도록 확인.
- C03(실수로 다른 대상자를 누를 수 있는 보호자): 잘못 배정한 직후 **단일 작업 Undo**.
- A21(화면낭독기 사용자): 대상자 선택·동의 상태·배정 결과가 텍스트/ARIA 안내로 제공되는지 코드 확인. **실제 TalkBack 검증은 미수행.**
- C07/A25(공용 기기 사용자): 프로필 분리만으로 로컬 건강정보 암호화나 접근통제가 해결되었다고 오인하지 않도록 경고 유지.

실제 사용자·의료인 30명이 참여한 것은 아니다. AI 코드 기반의 가상 Cognitive Walkthrough이며 성공률/만족도는 측정하지 않았다.

## 3. 안전한 수동 분류의 동작

1. **미분류 상태 보존:** legacy V1/V2 파일의 기록은 자동으로 A나 B에 배정하지 않는다. QA 화면에서는 실데이터가 아니라 화면 생성 시 준비된 예시 1건만 미분류로 존재한다.
2. **명시적 대상자 선택:** A/B 버튼으로 현재 대상자를 고르고 미분류 카드의 날짜·메모·가상 질문을 읽는다.
3. **동의 확인:** "내용을 확인했으며 현재 대상자에게 배정함을 이해했다" 확인란을 체크하지 않은 경우 작업 거부. 추가로 JavaScript 확인 대화상자에서 취소 시 원본 불변.
4. **원본 재확인:** 처리 함수는 선택한 레코드 ID와 사용자가 확인한 **원본 사본(Exact Snapshot)**이 현재 미분류 값과 완전히 일치하는지 검사. 불일치 시 덮어쓰기 없이 중단.
5. **원본 ID 보존:** 불변 복사로 미분류 배열에서 1건을 제거해 명시적 대상자 기록으로 1건 이동. 전체 기록 건수는 변하지 않으며 두 대상자에 이중 기록하지 않는다.
6. **되돌리기:** 현재 페이지 메모리의 마지막 배정 Undo 토큰을 사용. 대상이 배정 후 수정되었거나 중복 ID가 생겼다면 **거부**하여 다른 변경을 덮어쓰지 않는다. Undo 완료 시 미분류 목록의 원래 위치로 되돌린다.
7. **가상 초기화:** QA 화면에서만 가상 샘플 상태를 다시 생성. 실제 브라우저 저장소를 읽거나 초기화하는 코드가 없다.

**보안·규제 주의:** 비식별 A/B 라벨과 UUID는 사용자 인증이나 접근 권한 통제 수단이 아니다. 같은 브라우저를 여는 사람의 평문 localStorage 접근, 다운로드 파일, 클립보드, 화면 스크립트 공격 위협은 여전히 존재한다.

## 4. 자동 테스트 매트릭스 (합성 데이터)

| 시나리오 | 결과 | 증거 수준 |
|---|---|---|
| 두 가상 프로필 ID 생성 및 선택 대상 격리 | PASS | 기존 프로필 순수 함수 실행 |
| 미분류 기록 내용의 독립 사본 반환 | PASS | 원본 객체 불변성 검사 |
| 명시적 확인 없이 배정 시도 | PASS | 동의 검증으로 예외 발생 |
| 확인했던 원본 메모가 변경된 경우 | PASS | 스냅샷 비교 후 배정 중단 |
| 확인창에서 사용자가 취소 | PASS | 가상 DOM 상에서 기록 0건 이동 |
| A에 배정한 기록이 B 요약·복사에 들어가지 않음 | PASS | UI 상태 전환·요약 텍스트 검사 |
| 원본과 전체 기록 건수 유지 | PASS | 미분류 1건 감소·대상자 1건 증가 |
| 20건 저장 상한 보호 | PASS | 프로토타입 전역 한도 검사 |
| 마지막 배정 Undo | PASS | 미분류 원위치 복구 |
| 배정 이후 기록 수정 시 Undo 차단 | PASS | 예상 스냅샷 불일치 시 거부 |
| 가상 초기화 후 A/B·미분류 건수 초기 상태 | PASS | QA UI 시나리오 |
| 실제 사용자 기록 수정·이전·복원 | **미실행** | 명시적으로 금지·보류 |
| Android Chrome/iOS Safari 실기기 터치·TalkBack·VoiceOver | **NT** | 실기기 QA 전 |
| 복원/이전 시 완전한 DB 트랜잭션과 롤백 | **NT** | 현재 로직은 메모리 순수 함수. IndexedDB 실제 쓰기 없음 |
| 실제 보안 전문가·임상의·보호자 참여 | **NT** | AI 기반 사전점검만 진행 |

**PASS는 해당 JS 함수와 가상 DOM 테스트에 한하며, 실기기 사용자 테스트 또는 의료정보 서비스의 출시 적합성 인증은 아니다.**

## 5. UI 검증 절차 (QA 미리보기)

1. ApuDa Netlify Deploy Preview의 \`/memory/profile-qa.html\` 접근. 운영 \`/memory/\`와 별도이다.
2. 상단 A/B 버튼에서 **돌봄 대상 A** 선택, 최근 7일 기록 건수 3건 확인. 미분류 가상 기록은 1건이며 아직 A/B 모두에게 속하지 않음.
3. 미분류 가상 카드의 날짜·메모 확인 후 체크 없이 배정 버튼 클릭 → 거부 메시지.
4. 확인란 체크 후 배정 버튼 클릭, 시스템 확인창에서 **취소** → 기록 건수 불변.
5. 다시 확인하고 승인 → A 요약이 4건, 미분류가 0건. B로 전환하면 B는 1건 그대로이고 새 기록/질문이 보이지 않음.
6. A로 돌아와 **마지막 가상 배정 되돌리기** → A 3건, 미분류 1건 복귀.
7. "가상 기록 초기 상태로 다시 시작" → 원래 7일/A/미분류 1건 및 Undo 초기화.

**실제 환자 정보 입력 금지.** 화면의 모든 메모는 소스에 포함된 예시 문자열이다. 화면에서 A/B 배정했다고 해서 실제 기록의 대상자가 정해지는 것이 아니다.
