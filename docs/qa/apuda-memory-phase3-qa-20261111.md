## 구현 내용과 안전 경계

1. **로컬 검색**: 메모, 진료 질문, 수면·식사·복약 관찰 항목의 이름과 선택값, 기록 날짜를 검색한다. 복수 단어는 모두 포함(AND)해야 일치한다. Unicode 정규화(NFKC)와 대소문자 정리를 거친다.
2. **날짜 필터**: 시작일·종료일을 포함해 저장 목록을 좁힌다. 기간 역전 또는 유효하지 않은 날짜는 오류 메시지로 알린다. 필터 초기화 버튼을 제공한다.
3. **비파괴적 동작**: 검색어·날짜 필터는 화면 표시만 바꾸며 `localStorage`의 실제 기록을 수정·삭제하지 않는다. 기존 저장 키 `apuda-memory-care-diary-v1`, V1/V2 JSON 호환 정책, 20건 저장 상한을 유지한다. 검색 조건은 영구 저장하지 않는다.
4. **진료 준비 요약**: 최근 7일 또는 30일의 보관 기록에서 `기록된 날짜 수 / 저장된 기록 건수 / 작성된 의료진 질문 수`를 보여준다. 별도 질문 목록을 먼저 제시하고, 복사·인쇄용 텍스트에도 질문을 앞에 배치한다. 같은 날 다수 기록은 여러 건으로 계산하지만 기록 날짜는 1일로 센다.
5. **필터와 요약의 구분**: 진료 요약은 검색 결과에 한정되지 않고, 선택한 7일/30일에 속하는 **전체 보관 기록**을 기준으로 한다. 최대 20건만 보관하므로 해당 기간의 모든 사건이 기록되었다는 뜻이 아니다. 누락일을 정상 상태로 추정하지 않으며 임상 위험도·진단 점수를 만들지 않는다.
6. **개인정보 경계**: 서버 업로드·클라우드 동기화·암호화가 새로 추가되지는 않았다. 사용자가 복사하거나 출력한 진료 기록은 클립보드·인쇄물·PDF를 통해 노출될 수 있다.

## 30개 역할 틀에 따른 주요 AI 사전점검

`review-apuda`의 30역할 범주를 체크리스트로 참조했다. 암종별 S01–S12 역할의 임상 내용 심사는 이번 비진단적 돌봄 기록 도구와 직접 관련된 새로운 암종 콘텐츠가 없어 **범위 외**이다. 돌봄·약료(M03·M04), UX·접근성·개발·개인정보(D01·D03–D06), 환자·보호자(P01–P06, C01–C02)의 잠재 사용자 관점을 AI가 점검했다. **해당 인원이 실제 감수하거나 테스트한 것은 아니다.** 인지건강 분야 임상의 검토와 가족 실사용 검증은 별도 필요하다.

| 위험 ID | 위험과 영향 | 현 완화책 | 남은 과제 |
|---|---|---|---|
| R3-01 | 필터 결과를 실제 저장 전체 자료로 오인 | `전체 n건 중 m건 표시`, 변경하지 않는다는 안내, 필터 초기화 | 보호자 사용성 테스트에서 이해도 확인 |
| R3-02 | 검색 후 진료 요약도 함께 줄었다고 오인 | 검색·날짜 필터와 요약이 독립적임을 화면에 명시 | 서로 다른 날짜 조건의 실기기 시나리오 검증 |
| R3-03 | 7/30일 통계가 임상적 위험도 또는 완전한 일지로 오인 | 단순 저장 건수임을 명시, 최대 20건과 미기록일 한계 표기 | 의료진 안내 문구·용어 실제 확인 |

| R3-05 | 기록 복원·인쇄·화면낭독기에서 의도치 않은 손실·접근 불가 | 자동 회귀와 화면 라벨 점검 | 저장 기록 백업 후 휴대폰 복원·PDF·TalkBack 검증 |

## 출처 및 임상 범위

이 단계는 진료법이나 약물에 관한 새로운 의학 주장을 추가하지 않았다. 돌봄 질문 준비의 환자교육 배경 자료는 앞선 [Phase 2 AI 사전점검](./apuda-memory-phase2-qa-20261111.md)의 NIA(미국 국립노화연구소) 및 중앙치매센터 공식 자료를 따르며, 여기에 기초한 사용성 문구도 실제 임상 감수 완료로 주장하지 않는다.
