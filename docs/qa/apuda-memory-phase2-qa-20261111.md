# ApuDa Memory 2단계 AI 사전점검

- 기준일: 2026-11-11, Asia/Seoul
- 범위: `/memory/#care-diary`의 돌봄 기록 V2, 진료 준비 7일·30일 요약
- 변경 브랜치: `feat/apuda-memory-p0-20261110` / PR #293
- 공개 미리보기: https://deploy-preview-293--apuda-total.netlify.app/memory/#care-diary
- 배포: Netlify **Deploy Preview** 성공. 운영 배포·기존 논술 앱 자료 변경 없음.
- 검토 모드: **AI 사전점검**. 실제 전문의·환자·보호자 참가 검토 자료 없음. 실제 승인 아님.

## 주요 변경과 자료 보호

1. 기존 `localStorage` 키 `apuda-memory-care-diary-v1`과 기존 `{id,date,text}` 기록을 **그대로 유지**한다. 선택적 필드 `sleep`, `meal`, `medicationCheck`, `question`만 추가한다.
2. 수면·식사(평소와 비교한 관찰), 처방·복약 확인 상태, 의료진에게 물을 질문(최대 300자)을 기록한다. 기존 메모의 1,000자 제한, 사용자 동의, 20건 상한, 비자동 삭제는 유지한다.
3. JSON 백업은 **V2**로 내보내 새 필드가 구버전 복원기에서 조용히 소실되는 상황을 방지한다. V1의 올바른 기존 백업도 새 페이지에서 읽는다. 다른 기록 ID를 자동 덮어쓰지 않고, 용량 초과 시 복원하지 않는다.
4. 선택한 최근 7일·30일에 해당하는 저장 기록만 날짜별로 보여준다. 같은 날 여러 건이면 건수 그대로 센다. 빈 날짜를 정상 상태로 가정하지 않으며 질병 위험도 점수·진단 결과를 생성하지 않는다. 저장 가능한 전체 기간이 아닌 **현재 보관된 최대 20건의 부분 요약**임을 표시한다.
5. 진료 요약 복사 및 인쇄·PDF 요청 버튼을 제공한다. 데이터는 기기 내에서 정리하며 서버 전송 기능을 추가하지 않았다. 클립보드와 인쇄물의 노출 위험을 명시한다.

## 역할별 검토 범위와 위험 목록

30개 역할(암종별 S01–S12, 공통 M03–M06, 디자인·기술 D01–D06, 환자 P01–P06, 보호자 C01–C02)의 틀에서 이번 구현은 **인지건강·돌봄 범위**이므로 12개 암종별 콘텐츠는 검토 범위 밖이다. 인지장애 진료 전문가는 별도 실제 배정·승인을 받아야 한다. 구현 관련 AI 사전점검에서는 M03(돌봄), M04(약료), D01/D03/D04/D05/D06(UX·접근성·개발·보안) 관점을 적용했다. 사용자 경험 결론은 실제 참가자 시험 전 **가설**이다.

| ID | 사항 | 현재 상태 | 우선순위 | 다음 검증 |
|---|---|---|---|---|
| R-01 | `localStorage`와 백업 JSON은 암호화·기기간 동기화를 제공하지 않음 | 사용자에게 고지되어 있으나 민감정보 보관 위험 잔존 | P2 | 별도 보안 설계·위협 모델 검토 |
| R-02 | 30일 요약은 최대 20건 기록으로 전 기간 완전성 미보장 | 부분 자료임을 화면에 명시 | P2 | 보호자에게 누락·중복 날짜 이해 여부 확인 |
| R-03 | 복원·인쇄·파일 보관에 따른 사용자 실수 가능성 | 자동 테스트 완료, 실기기 결과 미검증 | P2 | 실제 Android 저장·복원·인쇄·PDF 리허설 |
| R-04 | 320px·200% 확대·화면낭독기 인터랙션 | 정적 CSS/라벨 점검 외 실기기 미검증 | P2 | TalkBack·키보드·확대·초점 수동 재검 |
| R-05 | 진료 요약이 의료진의 판단을 대체한다고 오인할 가능성 | 관찰·기록·질문용으로만 표기, 약 변경 금지 안내 유지 | P2 | 인지건강 전문가 임상 문구 승인 필요 |

## 다음 단계(운영 배포 전)

1. 기존 기록이 있는 휴대폰에서 새 필드 저장·이전 기록 조회·30일 요약을 확인하되, 실제 기록 삭제는 하지 않는다.
