## 3. 사용성 설계 세부

### 1단계: 위험 고지 3개를 사용자에게 각각 확인

- **공용 기기/평문 저장:** 실제 Memory의 현재 기록함은 브라우저 내 암호화 저장을 제공하지 않는다.
- **암호 분실:** 암호화된 가상 백업을 복호화하려면 해당 암호가 필요하며 마스터 키나 서버 복구 기능은 없다.
- **파일 저장 상태:** 다운로드 요청과 사용자의 기기 내 실파일 저장 확인은 다르다.

3개 체크박스를 모두 확인하기 전에는 “가상 기록 암호화 연습 시작” 버튼을 비활성화한다. 실제 의료정보·개인 비밀번호를 입력하는 UI는 없다.

### 2단계: 가상 대상자 A 전용 암호화·복호화

- 합성 A 기록 2건, B 기록 1건을 브라우저 메모리에서 만든다.
- 선택 대상 A만 전용 JSON으로 내보내고, B의 메모가 포함되지 않았는지 확인한다.
- \`encryptScopedBackup\` / \`decryptScopedBackup\`을 호출할 수 있는 HTTPS Web Crypto 환경에서 실제 암복호화한다.
- 암호화 파일 외부에 메모 내용이나 대상자 ID가 노출되는지, 복호화 결과 일치 여부, 다른 대상 선택 거부, 비밀번호 오류/변조 거부, 원본 불변 여부를 검사한다.
- 암호는 코드 안의 **공개된 합성 연습용 문자열**만 쓰며, 실서비스 키로 사용해서는 안 된다. 저장/파일 업로드/네트워크 요청/개인 건강정보 읽기 없음.
- 작업 결과는 \`role="status"\`와 \`aria-live="polite"\`로 제공하고 결과 제목에 키보드 포커스를 옮긴다.

### 3단계: *가상 파일만* 다운로드 요청

- 2단계의 **모든 검증이 완료된 경우에만** JSON Blob 기반의 가상 암호화 파일 다운로드 링크를 제공한다.
- 파일명에 **\`SYNTHETIC-ONLY\`**를 명시한다. 실제 개인 기록이 들어 있는 파일을 선택/업로드/복원하는 입력은 전혀 없다.
- 링크 클릭 후에는 “다운로드를 요청했습니다. 실제 저장 성공 여부는 확인되지 않았습니다”를 표시한다. **파일 저장 성공을 자동으로 확정하지 않는다.**
- 링크는 페이지 이탈 시 \`URL.revokeObjectURL\`로 해제하고 재실행할 때도 이전 링크를 폐기한다. 다운로드가 완료된 실제 파일은 브라우저 다운로드 폴더에 별도로 남을 수 있다.
- 실제 저장을 확인하는 절차는 사용자가 기기 파일 목록에서 가상 파일명 확인을 직접 수행한다. 업로드한 실제 기록의 새 기기 복원 시험은 **사용자 지시에 따라 보류**한다.

## 5. 고령 보호자 실기기 시험 체크리스트

실제 Android/iPhone에서 다음을 사람이 직접 확인해야 한다.

1. **가독성:** 360px 이하 화면에서도 3개 확인 문구의 잘림 여부, 200% 확대/400% 확대에서 재흐름 여부.
2. **스크린리더:** TalkBack/VoiceOver로 체크박스 상태, 비활성 버튼, 진행/실패 안내가 의미 있게 읽히는지.
3. **손 조작:** 48~52px 이상 터치 컨트롤, 포커스 표시, 조작 실수 시 이전 상태 보존.
4. **시간:** 19건 Web Crypto는 기존 17단계의 기기 테스트에서 수치 수집; 본 18단계는 2건의 안전 교육에 집중.
5. **다운로드:** 가상 암호화 파일의 다운로드 요청 후 실제 기기 파일 목록에서 보이는지 확인. **실제 환자기록 또는 평소 비밀번호 사용 금지**.
6. **실패/오류:** 비밀번호 오류, 네트워크 연결 끊김/탭 종료/브라우저 메모리 제한에서 실제 개인기록 영향이 없는지 검토.
7. **기기별 기록:** 기기 모델·OS·브라우저 버전·확대 비율·시험 시각·가상 데이터만 있는 스크린샷과 결과 구분.

## 6. 개인정보·보안 P0 및 출시 판단

현행 서비스를 기존 그대로 두었다는 사실과, 위험이 해결됐다는 주장은 구분한다.

- **R01/P0 평문 저장은 미해결:** QA 화면의 암호화는 기존 Memory의 평문 localStorage/JSON/TXT/PDF/클립보드 내용을 암호화하지 않는다.
- **R02/P0 대상자 혼합은 미해결:** 대상 분리·배정·백업 기능은 독립 QA 모듈일 뿐 실제 돌봄일지 전면 적용이 아니다.
- **R03/P1 동시 탭 충돌은 미해결:** 16단계 25회 시뮬레이션이 실제 브라우저 검증을 대신하지 않는다.
- 테스트용 \`noindex\`·개발 호스트 제한은 로그인/권한 관리/암호화를 대체하지 않는다.
- 가상 보호자 30인단 감수는 실제 30명에게 테스트를 의뢰했다는 뜻이 아니다.

\`docs/qa/apuda-memory-release-gates.json\` 현재 **15개 중 PASS 2개, PENDING/DEFERRED 13개 → 출시 NO_GO**. \`--require-go\` 검사는 조건이 충족되지 않을 때 exit code 2를 유지한다.

**출시 준비 단계:** 모바일 실기기·스크린리더와 의료·개인정보 전문가의 독립 검증, 복원 경로 및 위험평가의 명시적 승인 완료 후 다시 평가할 것. 현재 PR #293 Draft 유지·운영 미배포·기존 돌봄 및 논술 기록 변경 없음.
