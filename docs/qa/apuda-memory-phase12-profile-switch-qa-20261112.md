## 2. 선택한 대상자의 기록만 표시하는 구조

1. 임의 가명 ID(UUID v4) 2개를 가진 "돌봄 대상 A"와 "돌봄 대상 B"를 준비한다. 예시 메모·질문만 포함한다.
2. UI 전환 시 \`buildProfileSummary(vault, selectedProfileId, periodDays, localDate)\`를 매번 다시 호출한다. 다른 프로필 데이터에 대한 기본 조회 또는 "전체 보기" 호출은 없다.
3. 모듈 내부 \`scopedRecords\`가 올바른 프로필 ID만 받아 기록을 선택한다. 존재하지 않는 ID, ID 누락, 다른 프로필에 대한 기록 수정/삭제는 원천 프로토타입에서 거부된다.
4. 요약의 \`records\`, \`questions\`, 날짜별 \`daily\`, 복사용 \`buildProfileConsultText\` 모두 **선택한 대상자의 자료만** 포함한다. 미분류 가상 기록은 별도 1건으로 숫자만 보여주며 어느 대상자에게도 자동 배정하지 않는다.
5. 최근 7일/30일은 달력 날짜 기준 포함 범위를 사용하며, 기록이 아예 없는 날짜(\`day-missing\`), 기록은 있지만 필드를 선택하지 않은 항목(\`field-missing\`), 같은 날 복수 관찰(\`multiple\`), 일부 항목 미기록(\`partial\`)을 구분한다.
6. 선택한 프로필에 기록이 0건이라도 "정상"으로 해석하지 않는다. 전체 기록 상한이 20건이므로 30일 통계가 불완전할 수 있음을 명시한다.

## 3. 미리보기 화면의 주요 UI

- **가상 대상자 선택**: A / B 단추. 선택 상태에 \`aria-pressed\`를 사용.
- **기간 선택**: 최근 7일 / 최근 30일.
- **지표**: 실제 기록된 날짜 수, 해당 기간 저장된 기록 수, 날짜 기록 없는 날 수, 질문 수.
- **질문**: 해당 대상자만의 진료 질문 표시.
- **날짜별 관찰**: 최신 7일은 항상 보이고, 30일 선택 시 이전 23일을 펼쳐 볼 수 있음.
- **전달**: 선택한 가상 대상자의 텍스트만 복사하거나 인쇄하도록 구성.
- **표시·안전성**: 원본 화면에 없는 별도 QA 페이지; 실제 기록 입력 폼/백업·복원/임의 병합 없음.
- **접근 제한**: ApuDa Netlify Deploy Preview 정규 호스트명 또는 \`localhost\`/\`127.0.0.1\`에서만 가상 화면 실행. 다른 주소에서는 컨트롤과 요약을 숨김. \`noindex\` 메타태그 추가.
- **중요한 한계**: 페이지 접근 제한은 **가상 시연 화면 노출 제약**일 뿐, 인증·접근통제·암호화 대체 수단이 아니다. 페이지에 실제 의료정보를 넣지 않는다.

## 5. 출시 전 중요한 미해결 위험

**R02/P0:** 독립 QA 시연으로 대상자 간 기록 혼합을 방지할 수 있는 구조를 보였지만, **실제 Memory 사용자의 기록 분리 기능은 아직 없음**. 기존 JSON을 자동·무단으로 분류해서는 안 된다. 실제 사용자 화면에 연결하려면 사용자별 저장소·검색·요약·JSON 백업·복원·수정·Undo가 모두 정확한 프로필 ID를 사용한다는 통합시험, 기존 기록 '미분류' 표시, 명시적 분류 확인 및 안전 롤백이 필요하다.

**R01/P0:** 로컬 평문 기록, 비암호화 JSON/TXT 파일, 인쇄·클립보드 노출 위험은 그대로 남아 있다. 8단계 별도 암호화 모듈은 현재 사용자 UI에 연결하지 않았으며 독립 보안 검증도 완료되지 않았다.

**R03/P1:** 기존 \`localStorage\`는 원자적 동시 수정 보장을 제공하지 않는다. 9단계 IndexedDB 모듈은 테스트 전용이며 실제 서비스에 아직 연결하지 않았다.

**R04/P1:** 전체 기록이 최대 20건이므로 30일 요약의 자료가 반드시 30일치인 것은 아니다.

**보안 판단:** 이 프로토타입은 실제 환자정보 사용 전 안전성 증명이 아니며 출시 차단 게이트는 이전과 동일하게 유지한다. Netlify 무료 요금제 및 기존 학습/논술 기록에 영향 없음.

## 6. 향후 우선순위

1. 실제 Chrome·Android·iPhone Safari에서 가상 화면의 대상자 전환·복사·인쇄·시각/음성 접근성 QA.
2. 대상자 분리 로직을 기존 기록 관리에 **선택적으로** 연결하는 마이그레이션 설계. 기존 기록은 무조건 '미분류'에서 시작하며 사용자 확인 없이는 자동 배정하지 않는다.
3. 보안/개인정보 전문가 검토 및 별도 암호화 저장·백업 설계, 복구·패스프레이즈 분실 UX.
4. 실제 사용자의 진료 정보로 시험하지 않으며, 개인 데이터 복원은 요청대로 보류.
