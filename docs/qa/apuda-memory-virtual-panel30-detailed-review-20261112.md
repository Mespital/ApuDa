**유형:** AI 페르소나 30개를 활용한 코드 기반 Cognitive Walkthrough(인지적 과업 검토). 실제 사람 30명 또는 독립 AI 에이전트 30개가 참여한 것이 아니다.

## 1. 판정과 방법

**요약 판정: 배포 NO-GO 유지.** 가상 30개 사용자 여정을 기준으로 개선점 16개를 도출했다. 우선순위 분포는 **P0 2개, P1 8개, P2 6개**다. P0는 실제 사고가 확인됐다는 의미가 아니라 실제 사용 전 차단·해소 여부를 판단해야 할 **잠재적인 중대한 설계 위험**이다. P1 역시 실제 사용자 실패율이 아닌 근거 기반 위험 추정이다.

평가 기준은 ① 처음 찾아가기(Discoverability), ② 입력/수정·되돌리기(Task Continuity), ③ 인지·시각·운동 접근성(Accessibility), ④ 기록 무손실과 개인정보(Data Safety), ⑤ 진료 요약의 해석 안전성(Clinical Interpretability)으로 했다. 각 페르소나에 대표 과업 한 개와 예상 마찰을 붙였으며, 근거는 현재 PR 코드 또는 명확히 표시한 사용성 가설로 구분했다. 점수/실제 성공률/실제 과업 소요시간을 임의 생성하지 않았다.

### 실제 구현의 강점

- 수면·식사·처방 관찰 항목이 선택사항이며 질병 위험 점수를 임의 계산하지 않는다.
- 진료 질문 우선 노출, 7일·30일 요약, 날짜 기록 없음과 항목 미기록의 분리, 같은 날짜 복수 관찰 표시가 구현되어 있다.
- 기록 검색/날짜 필터는 저장 원본을 수정하지 않고, 저장 성공 후 필터를 초기화해 새 기록을 바로 보여준다.
- 수정·삭제 확인과 현재 페이지 내 최근 1건 Undo가 존재하며, JSON V1/V2 복원은 기존 ID를 덮어쓰지 않는 추가 방식이다.
- 공식기관 상담·긴급 112/119 연결 및 관찰표는 진단 도구가 아니라는 안내가 있다.
- 기기 저장·비암호화·서버 비전송에 대한 경고를 숨기지 않는다. 단, 경고만으로 개인정보 위험이 제거되지는 않는다.

## 3. 문제 등록부 (16개) — 코드 근거와 개선 수용 기준

표에서 ‘확정’은 코드에 현재 구현 또는 부재가 확인된다는 뜻이지, 실제 사고가 재현되었다는 뜻은 아니다. 상세 실제 기기 실패는 ‘NT’이다.

### R01 · P0 · 평문 건강정보의 브라우저·내보내기 노출

- **증거 수준:** 확정된 설계 제약 + 노출 사고 미확인; 코드 위치: public-site/memory/index.html L291, 307, 322, 527–545, 853–870.
- **영향/가상 사용자 관찰:** 기기/브라우저를 공유하면 메모·질문이 노출될 수 있다. JSON/TXT/클립보드·PDF도 별도 파일 또는 시스템 영역에 남는다.
- **권장 보완:** 개인용 기기 고지 강화, 보호된 파일 백업의 사전 검증, 인증·암호화·동의·보유기간 정책 확정. 실제 환자 기록 투입 전 보안 검토 게이트 적용.
- **수용 기준:** 공용 프로필에서 민감정보를 저장·공유하도록 유도하지 않으며 보안 설명이 정확하고 독립 검토 기록이 존재

### R02 · P0 · 돌봄 대상자별 기록 분리 부재

- **증거 수준:** 코드 구조 확정; 실제 사용자 혼합 사례 미확인; 코드 위치: public-site/memory/index.html L512, 979–1006, 1044–1071.
- **영향/가상 사용자 관찰:** 한 브라우저 키로 모두 저장하고 대상자별 스코프가 없어 부모 두 분·환자 두 명 기록이 한 요약으로 합쳐질 수 있다.
- **권장 보완:** 개인정보 없는 임의 프로필 코드로 분리, 기존 기록을 '미분류'로 보존, 수동 분류에는 확인과 롤백 필수. 자동 의료 대상자 추론 금지.
- **수용 기준:** 2개 가상 대상자 각각의 7일/30일 요약에 상대방 기록 0건 포함, 기존 기록 무손실 유지

### R03 · P1 · 멀티탭 동시 저장 시 갱신 손실 가능성

- **증거 수준:** 트랜잭션 부재 확인; 실제 경합 재현은 NT; 코드 위치: public-site/memory/index.html L527–551, 751–787, 1157–1163.
- **영향/가상 사용자 관찰:** 각 탭이 읽고 전체 배열을 다시 쓰는 read-modify-write이며 원자적 compare-and-swap을 보장하지 않는다.
- **권장 보완:** IndexedDB 트랜잭션 또는 동시수정 직렬화 전략, 충돌 표시와 재시도. 9단계 실험 코드는 아직 현재 UI와 미연결.
- **수용 기준:** 가상 2탭 동시 100회 저장에서 기록 누락·중복·상대 변경 덮어쓰기 0건

### R04 · P1 · 20건 상한과 30일 기록 요약의 구조적 불일치

- **증거 수준:** 확정된 기능 제약; 코드 위치: public-site/memory/index.html L325–340, 975–987.
- **영향/가상 사용자 관찰:** 하루 1회만 기록해도 최대 20일, 하루 2회면 10일 만에 한도에 닿는다. 30일 요약은 부분 기록에 그칠 수 있다.
- **권장 보완:** 장기 저장과 이전·백업 정책을 먼저 검증한 뒤 상한 재설계. 현재는 부분 요약 표지와 기록 총량 안내 강화.
- **수용 기준:** 30일 중 기록 누락과 저장한 건수를 정확히 구분, 상한 도달 시 무손실·명확한 다음 행동 안내

### R05 · P1 · 미저장 초안 보호 부재

- **증거 수준:** 자동 임시저장·화면 이탈 경고 코드 없음; 코드 위치: public-site/memory/index.html L297–309, 743–805.
- **영향/가상 사용자 관찰:** 통화·실수로 뒤로가기·탭 종료 시 아직 저장하지 않은 기록과 질문을 잃을 수 있다.
- **권장 보완:** 최소한 페이지 이탈 경고와 작성 중 상태 표시. 민감 정보 자동 임시저장은 별도 사용자 동의와 삭제 정책 검토.
- **수용 기준:** 가상 메모 작성 중 이탈·복귀 시 분실 위험을 명확히 경고하고 취소 시 입력이 보존됨

### R06 · P1 · 질문만 저장할 수 없는 필수 메모 구조

- **증거 수준:** 코드에서 확인; 코드 위치: public-site/memory/index.html L305–308, 765–767.
- **영향/가상 사용자 관찰:** 의료진에게 질문 하나만 남기고 싶은 사용자는 불필요한 메모를 입력해야 저장된다.
- **권장 보완:** 메모 또는 진료 질문 중 1개 이상을 필수로 전환하되 빈칸·백업·수정·요약 하위 호환성 시험.

### R07 · P1 · 목적 찾기와 첫 기록 진입의 화면 인지 부담

## 4. 사용자 유형별 종합 의견

**보호자 12명:** 원문을 남기고 의료진에게 질문을 전달하는 핵심 가치는 명확하다. 그러나 직장·야간 돌봄 보호자에게는 '저장하지 않은 입력'과 빠른 질문 기록, 여러 대상자 분리 문제가 더 큰 장애가 된다. 7일·30일은 기간 표시이지 20건 보관 정책을 해결하지 못한다.

**고령 당사자 8명:** 18px 본문, 큰 글자 토글, 단순 3개 관찰 선택지는 강점이다. 반면 한 페이지의 기능 종류와 설명량이 많고, 복약 확인의 의미·동의 반복·미저장 초안에 대한 인지적 부담이 남는다. 실제 글자 확대·인지 접근성 시험 전에는 사용자 친화성을 확정하면 안 된다.

**접근성·디지털 취약 사용자 5명:** 코드에 label, aria-live, focus, 반응형 CSS가 있으나 실제 화면낭독·400% 확대와 키보드 조작이 검증되지 않았다. 공용 기기 사용자는 개인정보 위협 때문에 기본 저장 방식이 부적절할 수 있어 대체 안전 경로가 필요하다.

**진료·지원 연계 사용자 5명:** 질문 우선 출력과 비진단 고지는 장점. 의료진이 받는 요약은 '전체 한 달 기록'이나 '복약 완료'를 뜻하지 않으며, 멀티 환자 기록 혼합은 특히 피해야 한다.
