## 구현 기능

1. **기록 수정(Edit)** — 저장된 기록의 날짜·수면·식사·복약 확인·메모·진료 질문을 같은 폼에서 수정. 기존 레코드 `id`와 브라우저 저장 키 `apuda-memory-care-diary-v1` 유지. 수정 시 저장 동의 재확인. 20건 한도에 도달해도 기존 1건 수정은 가능.
2. **수정·삭제 Undo** — 현재 페이지에서 **최근 수정 또는 삭제 1건**만 실행 취소. 되돌릴 원본은 메모리 변수 `pendingUndo`에 보관하며 localStorage·서버에 추가 사본을 저장하지 않음. 새 기록 저장 및 다음 수정·삭제 성공 시 이전 Undo는 교체/해제. 페이지를 닫으면 소실.
3. **데이터 충돌 감지** — 수정 시작 때 원본 스냅샷과 저장 직전 동일 `id`의 최신 원본을 비교하고 불일치 시 덮어쓰지 않음. 삭제도 사용자 확인 이후 다시 읽어 원본 변경 여부를 확인. Undo 시에는 대상 레코드가 현재 예상 상태인지 확인하고, 삭제 복구의 경우 ID 중복/20건 제한을 재확인.
4. **용량·장기 보관 안내** — 현재 레코드 수/20건을 표시. 15건부터 JSON 백업 권장, 20건에서 신규 저장 제한. 백업 파일의 실제 다운로드 여부를 확인한 뒤 사용자만 기록을 직접 정리하도록 안내. 자동 삭제 없음.
5. **접근성 및 동선** — 기록 카드마다 '수정'과 '삭제'를 구분하여 배치. 수정 상태/취소 버튼/Undo 상태를 노출. 삭제 후 초점은 기록 목록 제목으로 이동. 기존 18px 본문·52px 주요 버튼 및 브랜드 블루/네이비 유지.
6. **수정 중 Undo 충돌 예방** — 다른 기록을 편집 중 이전 작업을 되돌리려 할 때, 수정 초안이 있으면 사용자에게 취소 여부를 확인한다. 취소하면 초안을 유지하고, 승인한 경우에는 수정 상태와 초안을 정리한 뒤 되돌린다.

## 추가 안전 검토

**현재의 보안 한계**: `localStorage`는 암호화된 의료기록 저장 시스템이 아니다. 공용 장치·브라우저 프로필 공유·확장 프로그램·기기 분실 등에 대한 접근통제가 없다. Undo는 임시 메모리 복사만 제공하며 백업 및 영구 감사 로그를 대체하지 않는다. 복사된 건강정보는 시스템 클립보드에, 다운로드한 JSON/TXT와 PDF는 암호화되지 않은 파일에 남을 수 있다.

**동시성 한계**: 동일 페이지에서 저장 직전 기록을 재확인해 충돌 가능성을 줄였지만, 서로 다른 탭에서 밀리초 단위로 동시 저장할 때 완전한 원자성(atomic transaction)을 보장하지는 않는다. 여러 탭에서 동시 편집을 권장하지 않는다.

**의료적 의미**: 수면·식사·복약 확인은 보호자의 주관적 관찰이며, 앱이 치매를 진단하거나 약 변경을 제안하지 않는다. 진료 요약은 최대 20건의 부분 기록일 수 있고 '미기록'은 정상 상태가 아니다.

## 운영 반영 전 게이트

1. 개발 미리보기에서 가상 메모 1건을 수정→되돌리기, 삭제→되돌리기, 20건 한도를 확인.
2. Android Chrome 및 iPhone Safari에서 큰 글자·화면낭독기·화면 확대 후 작동 확인.
3. 2개 탭 동시 수정, 저장 공간 부족, 새로고침 후 Undo 소멸을 재현해 설명 문구와 일치하는지 확인.
4. 새 기기 복원은 사용자의 추후 승인에 맞춰 실행하며, 원본 백업 없이 기존 기록을 초기화하지 않는다.
5. 환자·보호자와 개인정보/임상 전문가가 실제 검증한 기록이 확보되기 전까지 최종 승인 또는 배포 완료 표시 금지.
