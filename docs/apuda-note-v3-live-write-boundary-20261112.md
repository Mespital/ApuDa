# ApuDa 환자 수첩 V3 실제 호출부 정리 — Draft 한정

기준일: 2026-11-12 KST · [Draft PR #294](https://github.com/Mespital/ApuDa/pull/294)

## 확인된 문제 및 변경
- 응급 체크리스트 `triage()`가 기본 건강 기록 키에 직접 `setItem()` 하여 공통 저장 경로를 우회함 → `save()` 호출로 변경.
- 대화 `saveChat()`이 저장 중 예외를 모두 무시함 → 원문 비교, 실패 시 화면 토스트 경고 및 최신 저장 원문 재로딩. **이미 화면에 표시된 미저장 메시지를 영구 보존하는 UI는 아직 없음**(P1).
- 건강 기록 `save()`도 마지막 로드 원문과 현재 저장 원문이 다르면 먼저 실패 처리하고 최신 기록을 다시 로드함. 이때 **이 탭에서 저장되지 않은 수정 내용은 화면에서 사라질 수 있어** 충돌 시 양쪽 사본 내보내기 UX가 필요함.
- `note-write-fence.js`는 `localStorage` 접근 권한을 주입받은 저장 경계 함수임. 한 번 더 읽고 실제 쓰기 및 읽기 후 검증을 수행하되, **compare-then-write가 원자적이지 않음**을 명시.
- V3 기본 화면은 기존 `localStorage`를 계속 사용. V4 / IndexedDB로 이전하지 않음.
- JSON 복구 `NOTE_STORAGE.replace/recover()`, Drive 복구, Reset All의 네 키 삭제, 오래된 Service Worker / 구형 탭의 기존 쓰기는 **그대로 남아 있음**. 이번 패치만으로 P0 해결 불가.

## 검증
`node tools/tests/apuda-note-v3-write-fence.cjs`
건강기록 연속 쓰기, 오래된 건강·대화 원문 차단, 무응답 저장, 용량 오류, 입력 유효성, 모듈 고립, **악의적 타이밍 끼어들기를 통한 P0 위험 재현**, 실제 V3 호출부 정적 연결, 응급 체크리스트, 스크립트 로드 순서 등의 12건 검사.

테스트에서 시간차 끼어들기는 **보호되지 않아야 한다는 진단 검사**다. 이를 일반적인 성공/안전성 보장으로 해석하지 않는다.

## 다음 작업과 배포 게이트
1. 중요한 모든 사용자 변경 경로가 저장 실패 시 수정 내용을 별도 내보내거나 재시도할 수 있도록 사용자 경험 개선.
2. 건강기록·대화·복원·복구·전체삭제를 통합 IndexedDB 트랜잭션에 연결하고 기존 V3 원문/체크포인트를 변경 없이 보관.
3. 구형 탭의 재접속 및 실제 Drive 자동 백업/prune이 새 구조에 미치는 영향에 대한 합성 테스트.
4. Chrome/Android/iOS 실기기 테스트 및 실제 사람 리뷰.

**원본/논술 기록과 실제 Drive 계정에는 접근·변경하지 않았으며, 운영 `main` 병합·Netlify 운영 배포를 금지한다.** AI D05/D06/D04 기술 사전점검, 실제 전문가 감수 아님.
