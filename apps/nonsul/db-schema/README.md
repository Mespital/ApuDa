# ApuDa 논술 기록 보존과 Netlify Legacy Free 배포

## 데이터 보존 원칙

- `20261102000100_create_nonsul_notebooks.sql`: 원본과 내용이 정확히 동일한 SQL 테이블 생성 스키마.
- `nonsul-state.netlify-database.mjs`: 원본 클라우드 동기화 서버 코드를 그대로 보관. 필요 시 인증된 별도 DB 환경에서 복구 가능.
- 이 디렉터리에는 **실제 사용자 논술 데이터가 포함되지 않습니다.** 브라우저에 저장된 원고나 사용자의 JSON 백업 파일은 건드리지 않습니다.
- `public-site/nonsul/` 안의 논술 화면/기기 저장 로직, `localStorage` 키, JSON 내보내기·불러오기, 로그인 함수 및 경로 설정은 변경하지 않습니다.
- 이번 변경은 브라우저 저장기록을 삭제하거나 Netlify Identity의 계정을 변경하지 않습니다.

## 무료 요금제의 빌드 장애

원인: 계정에 Netlify Database 사용 권한이 없는데 `public-site/package.json`에 `@netlify/database`가 설치되어 Netlify가 빌드 중 자동으로 DB 생성을 시도했고 `createSiteDatabase 403 Forbidden`으로 배포를 막았습니다.

조치: Netlify 자동 검색 경로의 SQL을 이곳으로 옮기고 **`@netlify/database` 의존성을 패키지와 lock 파일에서 제거**했습니다. 지원하지 않는 DB를 연결하는 기존 `nonsul-state` 엔드포인트는 기록을 읽거나 쓰지 않고 명시적으로 HTTP 503을 반환합니다. 기존 서버 코드는 바로 위에 원본 그대로 보관되어 있습니다.

**기기 기록은 계속 브라우저에 저장됩니다.** 이번 변경에 실제 DB 질의, DROP/DELETE, 원고 이관, 요금제 변경, 유료 서비스 요청은 없습니다. Netlify에서 DB가 없는 환경에서는 클라우드 동기화가 작동하지 않는다는 점을 사용자에게 알리고, JSON 백업을 기본 보존 수단으로 이용합니다.

## 원고 보호 지침

1. 논술을 작성한 원래 브라우저의 기존 앱 기록 화면(`/nonsul/old`)에서 **나의 기록 → 기록 내보내기**로 JSON 파일을 내려받으세요.
2. 백업을 확인하기 전 브라우저 데이터, 쿠키, `localStorage`를 지우거나 기존 브라우저 프로필을 초기화하지 마세요.
3. 테스트가 필요하면 **별도의 테스트 데이터**로 JSON 백업·복원을 확인하세요. 실제 사용자 원고를 덮어쓰지 마세요.
4. 로그인만 되어 있다고 클라우드로 기록이 저장된다고 가정하지 마세요. 이 무료 계정의 서버 클라우드 저장은 미지원입니다.
5. 훗날 DB를 지원하는 환경에서 클라우드 저장을 다시 켤 때는 실제 사용자 데이터 백업/중복 검사를 먼저 진행하고 원본 SQL과 handler를 재검토하세요.
