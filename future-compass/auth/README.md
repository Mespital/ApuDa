# 승준이 아지트 보호자 관리

## 처음 한 번: VPS 소유자 설정
기존 VPS SSH 터미널에서 배포 경로로 이동한 뒤 실행합니다. 실제 배포 계정의 홈 디렉터리 아래 `future-compass`입니다.

```sh
cd ~/future-compass
docker compose -p future-compass -f compose.yaml exec auth python /app/manage.py
```

보호자 비밀번호(12~128자)와 아이 PIN(숫자 4자리)을 각각 두 번 입력합니다. 입력 문자는 화면과 셸 기록에 남지 않습니다. 비밀번호를 채팅/이메일/소스 코드에 넣지 마세요. 초기 설정 전에는 인증을 요구하는 모든 페이지가 잠깁니다. 웹을 통한 최초 계정 선점은 불가능합니다.

## 평소 관리
https://future.apuda.app/login.html#parent → 보호자 로그인 → 새 PIN 두 번 입력 → 변경.
아이 세션을 모두 폐기하며 공부 기록은 유지합니다. 모든 기기 잠금과 보호자 비밀번호 변경도 가능합니다. 보호자 세션은 최대 15분, 아이 일반 세션은 최대 8시간, 선택한 개인 기기 세션은 30일입니다.

## 보호자 비밀번호까지 잊은 경우
VPS 소유자만 아래 명령으로 두 자격 증명을 다시 설정할 수 있습니다. 학습 기록은 삭제되지 않으며 모든 기존 로그인은 해제됩니다.

```sh
cd ~/future-compass
docker compose -p future-compass -f compose.yaml exec auth python /app/manage.py recover
```

## 저장 및 동기화
서버의 `~/future-compass/private/compass.sqlite`에 해시, 세션, 실패 횟수와 공부 기록을 저장합니다. 공개 dist와 Git 저장소에 포함하지 않습니다. 최초 연결 시 사용자가 이 기기/서버의 기록을 선택합니다. 연결된 화면에서 변경 사항은 약 3초 후 저장되며, revision 비교로 다른 기기 기록을 조용히 덮어쓰지 않습니다. 화면을 새로 열면 다시 연결합니다. 로컬 백업 파일도 유지하세요. 서버 디스크 장애 대비 별도 운영 백업은 필요합니다.

## 운영 보안 경계
* VPS 내부 8081 인증 서비스는 외부에 포트를 공개하지 않습니다. 8092는 loopback 전용입니다.
* 서버의 Caddy가 페이지/스크립트를 인증 후 제공합니다. 로그인 관련 파일 및 공개 공유 이미지, health만 예외입니다.
* Netlify는 기본 도메인과 배포 별칭에서도 동일 canonical HTTPS 주소로 강제 이동합니다. 기존 서비스워커는 폐기합니다. 이전 배포의 고유 주소는 과거 정적 콘텐츠가 남을 수 있으나 서버의 학습 기록/API에는 접근하지 못합니다.
* 예전 오프라인 복사본은 다시 온라인으로 연결해 업데이트해야 폐기됩니다. PIN은 휴대폰 OS 잠금이나 기기 암호화를 대체하지 않습니다. 기존 localStorage 기록은 기기에 남습니다.
* 서버 소유자는 DB에 접근할 수 있습니다. 서버 로그인 비밀과 아지트 비밀은 별개입니다.
* 보호자용 임시 URL, 공용 초기 PIN, 공개 reset endpoint가 없습니다.
* 변경 전 secret 파일은 만들지 않습니다. 웹 복구 이메일은 보내지 않으며 보호자 UI/SSH 복구만 제공합니다.

검증: `python future-compass/auth/test_auth.py` (접근 통제, CSRF, PIN 초기화, 세션 만료/해제, 영구 실패 제한, 기록 보존, 충돌 감지).
