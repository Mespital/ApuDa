## 검증

- `check.mjs`와 모든 `check-*.cjs/.mjs` 총 14개 진입점 통과. 최종 변경의 `check.mjs` 재검 통과.
- `check.mjs`에서 녹음 서버·회귀 검사를 실행하므로 Netlify/기존 CI의 기본 검사에서도 이번 실패 경로를 확인한다.
- `check-voice.mjs`: 실제 서버 엔진과 격리 HTTP RC fixture. 성공/부분/전체 실패, 원격 이름·크기·MD5·폴더, SHA-256 결과, 중복 없는 재시도, 지문 충돌, 재시작 중단·재전송, 48시간 경계·정리를 확인했다.
- `check-review-upgrade.mjs`: 실제 노트·녹음 보관함·Chat 수신 모듈을 모의 DOM/IDB/HTTP에서 함께 실행했다. 노트 페이지네이션, 4개 필드 수정 충돌, 결과 보존·명시 적용, 해시/IDB/저장 공간 실패, 새 인스턴스 상태 일치, PIN/엄마 비공개·삭제 노트 보호, 검증 중 지운 녹음의 재생성 방지, 네트워크/잘못된 결과, 비동기 Chat 수신을 확인했다.
- 대시보드: 이번 주 75분, 지난주 같은 요일까지 50분, 이후 요일 1,000분인 합성 자료로 같은 구간 비교 25분 증가를 확인했다. 숫자 표·접근성 이름·부모 비공개 출력을 검사했다.
- `git diff --check` 및 dist JS 문법·SW 자산 존재 통과.

외부 쓰기·Drive 삭제·실제 가족 자료를 시험에 사용하지 않았다. HTTP RC는 모의 원격 저장소이며 실계정 Drive 결과로 표현하지 않는다. 브라우저 Playwright 감사의 과목 선택자와 비동기 결과 대기는 갱신했지만 이번 실행에서는 해당 스크립트를 재실행하지 않았다.

## 운영 반영과 남은 인수 확인

저장소 인계 절차에 따라 Claude 검토 후 머지한다. Netlify 프런트와 VPS `live/voice.mjs`가 모두 배포되어야 한다. 프런트만 새 버전이면 이전 VPS 결과를 검증 정보 부족으로 거절할 수 있으며, 같은 버전 배포 후 기기 원본 재시도를 사용한다.

정식 PIN 뒤의 실제 녹음·모바일/태블릿·밝게/어둡게·화면낭독기·Drive 쓰기·삭제 시험은 아직 완료로 처리하지 않았다. Claude가 합성 음성으로 정식 1회 전체 흐름과 재시작/실패/충돌을 확인하고, 실제 파일 ID·이름·크기·원본 해시 및 노트·복습·보관함 상태 일치를 재검해야 한다. 일반 Chat 링크가 Chat/Work 모드를 강제로 선택한다고 안내하지 않는다.
