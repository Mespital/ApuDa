# 수업 사진 → 1분 기록·복습·다음 예습

2026-10-22 · Codex 구현 및 자체 검증. Claude 검토·머지 전이며 운영 반영 완료를 뜻하지 않는다.

## 승준이가 쓰는 방법

1. **오늘 → 📷 수업 사진·마지막 쪽**에서 과목을 고른다. **📷 사진 촬영**은 휴대폰의 후면 카메라 입력, **🖼️ 사진 선택**은 저장된 이미지 선택 입력이다. 선택한 뒤에도 두 버튼으로 다시 찍거나 바꿀 수 있다. 실제 선택 화면은 기기·브라우저가 제공한다.
2. 사진 용도를 고른다. **오늘 여기까지**는 수업 마지막 쪽, **중요한 부분**은 핵심 개념·문제·필기 자료다. 자동으로 읽힌 글을 확인하고, 보이는 쪽 번호를 직접 확인해 입력한다. 쪽 번호 없이 사진만 저장해도 된다.
3. 사진만 저장하거나 **이 사진에 1분 말하기도 추가**를 누른다. 1분 말하기에서 시작했어도 **수업 사진도 함께 남기기**를 펼쳐 사진을 붙일 수 있다. 말한 글과 사진에서 읽은 글은 따로 보관한다.
4. 이미 저장한 녹음·워치 메모는 **복습 → 수업 노트 → 이 메모에 수업 사진 추가**로 연결한다. 원래 말한 글·녹음·직접 고친 정리·복습 날짜는 유지한다.
5. **이 기기에만 저장**하면 사진·노트·복습 일정이 연결된다. 사진 내용까지 정리하고 Drive에 보관하려면 **노트 저장 · 채팅·Drive로 보내기**로 전달 자료를 준비하고, 안내된 요청을 일반 Chat에 보내 이어간다. 실제 저장·결과 회신이 확인돼야 Drive 완료로 표시된다.

## 반영 규칙

- 새 노트는 선택한 수업일 기준 **1·3·7일 뒤** 복습 일정을 만든다. 체크를 바꾸면 해당 날짜만 만든다. 기존 메모에 사진을 붙일 때는 기존 일정을 유지한다.
- 같은 **과목명·수업 날짜**의 사진과 1분 기록을 묶어 복습 정리 화면과 다음 수업 예습에 보여준다. 교시별 자동 병합이나 서로 다른 과목명의 자동 추측은 하지 않는다.
- 마지막 쪽 **86쪽**을 확인해 저장하면 **오늘 → 더 보기 → 내일 예습**에 **예습 출발: 87쪽의 소제목 확인**이 표시된다. 실제 다음 수업 범위는 선생님 안내로 확인한다.
- **중요한 부분**의 쪽 번호는 진도를 앞당기지 않는다. 진도는 가장 최근에 확인한 마지막 쪽을 사용한다. 쪽 번호를 사진·OCR에서 자동 확정하거나 보이지 않는 다음 페이지 내용을 만들어내지 않는다.
- 한 노트에는 사진 한 장을 담는다. 여러 장은 같은 날짜·과목으로 각각 남기면 함께 연결된다. 앱에 저장하는 사진은 기존 방식대로 압축된 JPEG다.
- 사진을 붙인 직후 기존 음성 정리가 사진까지 검토한 정리로 보이지 않게 안내한다. 전달 후 사진·쪽 번호가 바뀌면 늦게 온 예전 결과는 자동 적용하지 않는다.

## 저장·접근 보호

기존 `fc_notes_v1`, `compass-study-v1`, `fc_planner_v1`, `fc-notes-photos`를 사용한다. 사진을 먼저 새 자산 ID로 쓰고 노트·복습·날짜 저장이 실패하면 변경을 되돌린다. 저장 중 중복 제출과 역할 변경, 기존 메모 동시 수정을 검사한다. 사진 초안은 IndexedDB에 보관해 새로고침 뒤 복원하며 사진 복원 중에는 저장을 기다리게 한다. 저장된 노트에 사진을 붙이는 작업은 별도로 쓰던 초안을 지우지 않는다.

엄마 화면에는 사진 입력·수정 버튼을 제공하지 않는다. 복습 공유를 끄면 사진·읽은 글·사진에서 유래한 쪽 번호도 예습/공유 요약에 노출하지 않는다. 기존 OAuth·토큰·공유 권한 설정은 확장하지 않는다.

## 검증 근거와 한계

- 저장소 루트에서 `node future-compass/scripts/check.mjs` 및 `scripts/check-*.mjs`, `check-*.cjs` 전체, 총 15개 실행 지점 통과.
- 새 회귀 검사는 실제 note/helper/handoff 코드를 VM에서 실행한다. 사진 단독·녹음+사진·기존 메모 연결, 사진과 3개 저장 경계별 실패/롤백, 기존 사진 보존, 중복 저장, 동시 수정, 역할 전환, 한국시간 복습 날짜, 중요한 사진의 진도 분리, 공유 제한, 늦은 정리 충돌, OCR 결과 격리와 audio+JPEG+수업 범위 전달 자료를 검사한다.
- 브라우저에서 사진 선택으로 실제 PNG를 불러와 JPEG 미리보기·노트 저장·사진 재조회, 사진→말하기 전환, 사진과 글 초안 새로고침 복원, 기존 메모 연결 후 원래 정리 유지, 86→87쪽 예습 표시, 복습 정리의 같은 수업 자료 버튼을 확인했다.
- 390px 엄마 화면의 밝게·어둡게 모드에서는 비공유 복습 안내만 표시되고 사진·사진 추가 버튼·수업 자료 연결 영역이 없는 것을 확인했다.
- 촬영 입력은 `accept=image/*, capture=environment`, 사진 선택 입력에는 capture가 없음을 실제 DOM에서 확인했다. 카메라 촬영·마이크 녹음의 실물 휴대폰 동작은 별도 확인이 필요하다.
- 양식은 360·390·820·1180px, 밝게·어둡게 확인했다. 측정한 양식에 가로 넘침, 12.5px 미만 정보 글자, 44px 미만 활성 입력/버튼이 없었다. 최종 390px 촬영/선택 버튼은 각 44px 높이였다.
- 브라우저 자료는 예시 데이터이며 외부 API·Drive 전송을 막았다. OCR 성공 경로는 고정된 인식 결과로 검사했으므로 실제 필기 인식 정확도·실제 Drive 저장 성공을 검증했다고 볼 수 없다. HTTP 미리보기에서만 기존 앱의 `crypto.randomUUID`를 보완했으며 운영 코드에는 해당 보완이나 예시 데이터가 들어가지 않는다.

## Claude 검토·배포 인계

1. 위 세 입력 방식과 촬영/사진 선택을 실물 휴대폰에서 확인하고, 복습 비공유 상태의 엄마 화면을 확인한다.
2. 화면 자산과 `netlify/lib/study-handoff-core.mjs`를 **함께** Netlify 배포해야 수업 범위·별도 사진 메모도 Drive 전달 자료에 남는다. 이번 변경으로 VPS 서버 설정이나 새 Google OAuth 설정은 필요하지 않다.
3. 서비스워커는 `future-compass-20261022-v127-lesson-photos`, 자산 137개다. 워치 개선 PR #222는 별도 열린 PR이다. 두 PR의 `talk-note.js`, `scripts/check.mjs`, `sw.js` 충돌 시 양쪽 변경과 워치 CSS·lesson helper/CSS를 모두 보존하고 캐시 버전을 새 값으로 유지한다. 한쪽 전체 파일로 덮어쓰지 않는다.
4. 저장소의 `docs/codex-handoff.md`에 따라 Claude가 검토 후 머지한다. 실제 운영 배포와 Drive·카메라·워치 실기기 확인은 자체 검증과 구분해 기록한다.
